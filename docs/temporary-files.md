# 临时文件

产品含义见 [临时文件](https://github.com/gantrol/aiy-docs/blob/main/concepts/temporary-files.md)，交互见 [临时贴贴](https://github.com/gantrol/aiy-docs/blob/main/design/pages/temporary-content.md)。实现核对日期：2026-10-03；本文描述工作树接线，不表示已发行或完成原生窗口验收。

## 入口与边界

应用图标菜单 → AIY 花花 → 临时文件可新建便签、导入 Markdown／图片，以及从剪贴板建立临时文件。“我的花瓣”提供临时文件页，设置 → 维护复用同一管理组件。尚无可用空间时，标题栏提供临时文件入口。

导入 Markdown 明确创建可编辑的本机副本，保留来源路径，不回写原文件。支持 UTF-8 文本与同目录范围内的相对 PNG、JPEG、WebP、GIF 图片；不支持的本地依赖会报错，已经保全的临时稿仍留在管理列表。系统文件关联、直接只读打开原文件、原文件编辑及截图采集不是该导入入口的能力。

便签复用共享编辑器，图片复用现有媒体工作面；虚线表示临时状态。图片可以转为便签继续编辑，这不改变其临时身份。置顶、缩放、收起和隐藏沿用窗口命令。跨空间的图集归属和正式内容引用在转常驻后由普通内容入口提供。

临时 PNG／JPEG 贴图已接入[本地图片编辑](image-editing.md)，保存原图、可编辑标注、已采用结果和未完成工作稿。转图文采用当前结果；转常驻前完成采用，并先将原图与编辑记录保全到目标空间。其他格式和普通图片入口按该实现说明的范围判断。

## 保存与容量

主进程 `temporary-files/` 负责本机内容，`desktop-petals/` 继续负责窗口。数据位于应用数据根的 `temporary-files` 子目录，不创建隐藏空间或正式文章。预览与安装版是否共享这些文件取决于实际应用数据根，见 [开发说明](development.md#preview-与安装版的边界)。

每份内容有 UUID 清单、独立正文与检查点、已接收附件。正文先异步写入并确认，再原子替换清单；原正文在清单提交后才释放。检查点确认仅代表已落盘的输入。启动只读取清单，正文按窗口需要读取；未提交的中间文件仅在所有清单成功读取后回收。清单损坏时保留文件并报错，不以空目录继续写入。

初始容量为 512 MiB，可在维护页改为 16–16384 MiB。计数包含已接收正文、检查点、附件及生成的静态图片预览。关闭的未编辑参考图片按记录时间成为容量回收候选；打开、正在操作、已编辑或转换尚未完成的内容不参与回收。既有手写稿继续保存，即使超过上限；新增内容与附件会被容量限制阻止。丢弃有单独确认，隐藏窗口不丢弃内容。

## 转为常驻

菜单显示当前目标空间名称；没有可用空间时打开主窗口，让用户选择空间后重试。转换先要求编辑器完成保存，再持有目标空间操作许可，迁移实际引用的图片与文件，调用现有图片导入和便签创建入口。图文中的结构化图片身份、Markdown 图片路径和附件引用一并更新。

本机记录先保存转换意图，正式内容沿用已有幂等请求身份。正式内容与窗口布局确认后，原窗口切换到正式身份，临时记录才退出容量管理。窗口位置、尺寸、缩放与当前置顶选择沿用；编辑器按块位置恢复光标和滚动位置。目标已存在时先要求其窗口保存，再合并重复入口。

正式便签尚未创建的失败允许继续编辑临时稿；正式目标已经产生或图片转换结果尚未确认时保留原稿并锁住正文，用户在同一空间重试“转为常驻”。恢复或重试不创建第二份便签。临时记录清除后的遗留文件清理失败不回滚已成功的正式保存，下一次启动继续回收。

本批采用现有单元、组件、集成测试以及类型、静态和生产构建检查。未新增测试代码；原生窗口恢复、实际剪贴板与系统文件对话框、转换时的光标连续性仍需授权后的运行验收。
