# 日历：动态与本地用量

日历现在是当前本地空间的只读动态入口。它展示 AIY 已保存的业务变化，并可附带查看本地 AI 运行用量；作品、任务、运行和媒体仍由各自业务服务负责保存。

计划、手记、添加条目、未安排列表、重复规则、提醒与日历内插件报告已经下线。日历不会创建待办、补录人工事件、调度通知、执行发布或调用模型。

## 页面结构

页面只保留一套布局：连续日期热力图、日期滚轮和选中日动态列表。

- 热力图通过 `summary()` 读取 364 日窗口，数量不受明细分页影响。
- 选中日通过 `query()` 每页读取 100 条，首屏显示八条，其余已加载内容按需展开。
- 默认“当日回顾”会把同一天、同一业务对象的多条操作聚合为一条动态；同名但身份不同的对象不会合并。
- “记录历史”按实际入库日显示业务操作及动态更正，不进行对象日聚合；资料包内部写入仍只保留在审计中。
- 可定位来源提供“继续”和“打开当前来源”；来源有效但不支持直接打开的记录仍可查看详情。
- 图片和图片素材显示静态缩略图，使用现有媒体缩略图协议；缺失或已删除来源不会读取原图作为后备。
- 动态标题使用“对象名 - 类型／动作”。素材图集与创作目录按实际用途区分；图片通过生成、导入或处理成果的明确关系解析唯一创作项名称，多归属时保留素材名称，不按引用关系猜测归属。名称取自当前来源，不表示事件发生时的旧名称。
- 图集成员的加入、恢复、移除和排序归到所属图集；同日摘要保留各实体类型与操作的记录次数。列表显示前三类变化，详情显示完整计数，例如“加入成员 × 5”“新增提示词版本”“修改图文正文”。计数表示保存的操作次数，不表示去重后的成果数或正文差异。
- 当前来源缺失、已删除或无法解析的记录不进入日历列表和热力图，避免“对象／集合／图文版本（来源不可用）”按不同 ID 大量占位。有效但未命名的对象仍保留，历史回看使用“历史名称未记录”标题。日历不读取事件载荷或扫描全文来猜测改名前后名称、增删段落和未保存的历史内容。
- 命名视图保存时区、类别、时间轴、周起始日及用量显示偏好。旧 `view` 字段读取时兼容并丢弃，不再切换页面布局。

动态色阶表示当前筛选下的记录密度，不表示效率、成果或工作时长。聚合条目的首末记录时刻只描述已保存操作的范围，两者间隔不是持续工时。

## 时间轴和历史回看

`timeAxis: 'effective'` 按动态的当前显示日期查询。没有日期更正时使用原事件时间；有日期更正时使用用户明确选择的显示日期。

`timeAxis: 'recorded'` 按原活动或更正实际写入时间查询。更正和作废本身也是一条记录动作，因此会出现在对应记录日。

`knownAt` 提供“截至某时，本机已经保存了什么”的只读回看。它只使用截止时刻前已有的活动与更正，不能重建未采集操作、旧正文、历史目录关系或当时未保存的账单。历史回看不使用当前对象名称冒充旧名称；来源导航仍指向当前来源。

两个时间轴及历史回看都以当前来源有效性决定记录是否可见，不表示还原了来源在过去的存在状态。日历过滤不删除原始审计事件或更正历史；来源恢复有效后，对应记录可再次显示。

日期范围包含首尾，最多 366 日。定时时间保存为标准 UTC 时刻并携带 IANA 时区；全天记录保存日历日期。查询会按所选时区换算真实日界。

## 动态更正

单条动态可以追加更正说明、可选显示日期和作废标记。更正必须说明原因，使用修订号做乐观并发检查，并同时追加不可变修订；原事件身份、原记录时间和来源不会被覆盖。

同一对象日的聚合动态可能包含多条底层操作，因此不能从聚合行直接更正整组。切到“记录历史”后可查看并更正具体操作。

取消显示日期更正会恢复原事件时间依据。作废只影响动态显示，不修改来源业务状态，也不删除原始 `change_events` 或本地用量事实。

## 自动采集与来源

自动动态以 `change_events` 为主要依据。文件型业务可另外保存观察时间与首次成功写入空间库的时间。跨文件与 SQLite 的采集使用稳定事件 ID 去重；外部文件成功和空间库记录并不假装成一个事务。

来源解析只读取受信类型和准确 ID，不从事件载荷读取正文，也不按同名对象猜测关系。`DELIVER`、`COMPLETE`、`SUCCEEDED` 等操作标签只表示原业务保存的状态，日历不据此推导平台已发表或用户目标已完成。

来源有效性在对象日聚合、分页和日计数之前统一过滤。当日回顾保留有效父对象下的成员移除等变化；记录历史按原始实体的可解析来源过滤。检查按类型分批读取来源 ID 和有效状态，不加载全年对象名称、正文、图片归属或缩略图；这些展示信息只为当前明细页解析。

资料包同步按显式 `syncRunId` 保存一个终态动态。批次 ID 同时传入安装尝试的 `transaction_id`；详情读取独立保存的资料包名称、版本和成功／失败／中断状态。批次未结束时不显示成功动态，没有实际更新的成功检查不新增动态。内置包批量导入使用 `importBuiltinContentPacks(paths)`；fixture 批次使用 `importFixtures(fixtures, 'BUILTIN')`，不能把同一次同步拆成多个独立调用。

两个时间轴和热力图统一排除资料包关联、版本注册、安装状态内部写入、包注册／元数据更新、安装开始及空间注册身份对齐。细粒度 `change_events` 完整保留。有批次记录的安装尝试由批次终态替代；没有批次 ID 的旧记录只显示可确认的单包终态，不按时间相近推测为一个批次。历史回看可以读取已结束批次的保存快照，不展示当前图片缩略图冒充历史版本。

## 本地 AI 用量

本地用量按运行开始日归入所选时区。来源、模型和对象筛选直接作用于保留的运行记录；未知、零值、部分 Token、失败运行与未关联对象保持区别。

历史回看时隐藏当前用量，因为运行表没有保存每个过去时刻的完整已知状态。插件的账户费用、额度与导入报告不进入日历页面，也不与空间本地运行自动合计；插件设置仍负责连接配置。

## IPC 合同

日历 renderer 只使用以下接口：

| 接口                                    | 责任                                                              |
| --------------------------------------- | ----------------------------------------------------------------- |
| `query`                                 | 按日期、时区、类别、作废选项、时间轴和可选 `knownAt` 分页读取动态 |
| `summary`                               | 对整个日期窗独立计算动态日数量                                    |
| `correctActivity`                       | 为单条自动动态追加说明、显示日期或作废更正                        |
| `history`                               | 分页读取单条动态的更正修订                                        |
| `getPreferences` / `savePreferences`    | 读取和保存显示偏好                                                |
| `listViews` / `saveView` / `deleteView` | 管理命名视图                                                      |
| `usage` / `usageRuns`                   | 读取本地 AI 用量摘要与运行明细                                    |

所有调用都携带空间 ID，主进程会与当前活动数据库再次核对。preload 和主进程分别校验输入与返回结构。游标绑定数据库实例、筛选和状态修订；状态变化后旧游标返回失效，renderer 必须重新读取。

不再存在 `saveEntry`、`saveOccurrence`、`unscheduled`、`getEntry` 或提醒列表／操作 IPC。

## 持久化

当前读取和写入责任如下：

| 数据                                      | 责任                                   |
| ----------------------------------------- | -------------------------------------- |
| `change_events`                           | 自动动态的稳定身份、来源、操作与原时间 |
| `calendar_file_event_times`               | 文件事件首次成功写入空间库的时间       |
| `calendar_activity_overrides`             | 动态当前显示解释                       |
| `calendar_activity_override_revisions`    | 不可变的动态更正历史                   |
| `calendar_preferences` / `calendar_views` | 当前偏好与命名视图                     |
| `pack_sync_runs`                          | 同步批次身份、终态与资料包结果快照     |
| 本地运行表                                | AI 用量原始事实；日历只读              |

旧版本创建的 `calendar_entries`、系列和提醒表不会被当前功能读取、修改或清空。它们只作为已有本地数据保留，避免功能下线时破坏用户历史。旧偏好或命名视图中的 `kinds`、`view` 字段在读取时被接受并丢弃，下一次保存只写当前动态偏好。

## 设计工作台

运行项目已有的 design-lab 后打开 `/calendar.html` 可以使用内存合成动态和用量查看组件，`?locale=en` 切换英文。工作台不读取真实空间、不访问账户，也不发送系统通知。
