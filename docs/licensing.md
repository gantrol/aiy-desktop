# 软件许可与插件例外

AIY 采用 [GNU AGPL 第 3 版，仅此版本](../LICENSE)，附带 [AIY Plugin Exception 1.0](../LICENSE-PLUGIN-EXCEPTION)。插件例外是 AGPL 第 7 条允许的附加许可；上述英文许可文件共同构成授权条款，本页解释项目中的适用边界。

## 使用与分发

允许个人和企业使用、修改、分发及收费。用户用 AIY 创作的文章、图片和其他自有内容，不会仅因使用 AIY 而适用 AGPL；第三方素材、模型与服务仍按各自条款使用。

分发 AIY 或其修改版时，应履行 AGPL 的对应源码、版权、许可证及修改声明义务。修改版支持用户通过网络远程交互时，还须按第 13 条向这些用户显著提供免费获取对应源码的机会。对应源码应匹配实际分发或运行的版本，并包含必要构建脚本，不能仅链接未经修改的上游版本。

## 独立插件

独立开发、通过插件接口、扩展 manifest、贡献点或已记录的宿主 API 接入的插件，可以采用作者选择的许可证，包括闭源商业许可证，也可以收费、随宿主分发或提供网络服务。仅因这些交互，不要求公开插件源码或将插件改为 AGPL。同进程运行或依赖 AIY 才能工作，本身不取消该例外。

为接入接口而复制或改编非可执行的类型声明、manifest schema 等接口描述，适用例外中的专门许可；应保留已有版权声明。这不允许把宿主实现、业务逻辑或其他素材搬进插件后闭源。

对 AIY 宿主及其适配器的修改继续适用 AGPL。仓库内已有扩展默认沿用本仓许可，另有明确声明的除外；目录名含 `extensions`、拥有插件 ID 或随应用打包，不会自动赋予闭源改许可权。第三方依赖也不会因本例外而变更许可。

许可允许闭源插件，不代表运行时已支持任意插件代码。当前本地能力包通过经过校验的 manifest 绑定宿主运行时，语言包提供消息目录；安装、权限、安全和能力范围继续遵守现有实现。

## 包声明与交付

由于插件例外是项目自己的附加许可，根 `package.json` 与锁文件使用 npm 支持的 `SEE LICENSE IN LICENSE`，指向完整条款，不使用未注册的 SPDX 例外名称。[npm 许可字段](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#license)

桌面打包配置同时携带 `LICENSE`、`LICENSE-PLUGIN-EXCEPTION` 和 `THIRD_PARTY_NOTICES.md`；Windows 与 macOS 共用这一资源配置，应用归档内也保留与包声明对应的许可文件。浏览器伴侣构建从仓库根目录复制同一组文件到产物根目录，不单独维护许可副本。发布时仍须提供该版本的对应源码，并核对实际产物及下载入口。原样保留第三方许可与版权声明；重新授权已有外部贡献，需要有相应权利人的授权依据。

此前已经分发的版本仍可按取得时的许可使用；本次变更不会撤销这些既有许可。具体发行版本以该版本随附的许可文件为准。
