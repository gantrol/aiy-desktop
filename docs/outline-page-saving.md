# 大纲保存接续与同节点并发实施方案

本文的保存责任与当前边界描述已有节点转页面接线；后续章节为待实现的同节点并发方案，不表示合并或完整恢复已经通过。共同阶段及历史规则见[同节点并发修改方案](https://github.com/gantrol/aiy-docs/blob/master/architecture/content-concurrency.md)，业务标准见[必过用例](https://github.com/gantrol/aiy-docs/blob/master/quality/content-concurrency-acceptance.md)。本页维护桌面的代码接线和兼容边界，不另定义一套产品规则。

节点转页面先保存当前输入，再通过现有数据库事务创建页面、替换源分支并保存源修订。转换确认之后，源会话先接收新稿，工作区再打开新页。导航不能再次提交转换前的编辑器快照。

## 保存责任

`ArticleEditorSessionRuntime.mutateStructure` 复用 `AutoSaveCoordinator.mutate`，让前置保存、结构请求与确认进入同一会话的写入队列。请求仍携带预期修订；其他窗口或 Agent 抢先写入时，数据库继续拒绝过期基准。

收到结果时重新采集会话的当前输入，并立即标记外部修订，阻止排队保存使用转换前的基准。队列空闲后，没有新增输入的会话装载转换后的源稿；有新增输入、输入法组合或冲突的会话保留本地稿和外部结果，通过现有恢复入口处理，不强制覆盖。

`useArticleOutlinePageCreation` 属于大纲工作区，生命周期独立于正文编辑器的重建。它在收到转换确认后宣布新页，再请求并排打开；这条已提交导航不调用通用导航的前置保存。工作区校验原空间、标签、导航条目、来源作品及当前激活标签，异步打开结束时仍复核导航状态。切换位置、关闭或卸载会取消迟到导航，不撤销已经完成的数据库事务。

转换后的打开失败只报告打开失败，源稿确认已经处理。原编辑器的选择范围检查、输入法稳定要求和数据库修订校验继续有效。

## 当前边界

- 这是保存接续修复。同节点独立文字与格式合并、语义依赖核验、Agent 重算和按来源撤销尚未接入。
- 写入队列协调当前 renderer 的共享会话，不能取得其他窗口或 Agent 尚未提交的输入；这些写入仍由修订检查兜底。
- 转换期间新增输入会保留为待处理本地稿，尚不把转换步骤自动映射到它上面。触发转换的编辑器沿用请求期间的短暂只读，其他视图仍可能编辑。
- 数据库按请求身份和载荷判定重放。renderer 的未确认请求仍仅保存在编辑器内存；若回执丢失后已进入保存冲突，或编辑器重建、应用重启，自动核对原请求与恢复转换仍未贯通。不得把重新点击、生成新身份或恢复旧稿当作安全重试。
- 现有保存、编辑会话与大纲链接回归不直接覆盖节点转页面的完整保存和导航时序；类型检查与构建也不能替代该专项验收。

完整业务标准见[同节点并发用例](https://github.com/gantrol/aiy-docs/blob/master/quality/content-concurrency-acceptance.md)，尤其 CC-17～CC-20 与 CC-25。未执行的变体不因本次修复变为通过。

## 协调和提交协议建议

main 负责持久任务、回执、权限及保存事务，renderer 负责活动编辑输入与步骤。main 按空间和作品登记实际会话，核对会话身份及有效性后才发送候选；登记失效或另一窗口未纳入协调时保留候选。数据库无新修订不能被当作没有未保存输入的证明，超时也不等于窗口没有输入。

协议至少区分任务身份、生成尝试、候选采用组、提交请求，以及保存基准 `revisionId`、会话 `sessionEpoch`、草稿 `draftSeq` 和步骤版本。步骤位置与捕获的 B 必须属于同一文档版本；B 含未保存输入时保存准确快照及必要依赖。新接口只接收明确目标、范围、依据、候选和结果，不暴露通用 IPC 或底层任意编辑命令。

建议采用流程如下：

1. main 保全任务依据与候选；renderer 在输入稳定后取得 H，并在队列外进行有界的变化分析。耗时计算不阻塞主进程或界面线程，模型生成不占用保存队列。
2. 进入会话协调，核对空间、对象、授权、保存基准及输入版本，准备明确的采用组。异步保全采用意图后再次核验；输入已变化则重做检查，不能复用过期位置。
3. 由宿主构造编辑事务，标记来源和采用组，保护选区、组词与各自撤销上下文。映射或应用失败的组保留原意图；不能把被跳过的步骤记为全部采用。
4. 捕获本次实际快照，与采用组关联后交给保存队列；同一事务确认修订、必要关系、采用事实和回执。界面中的待保存采用不提前显示为已保存；期间新增输入继续保留。
5. 按准确请求和草稿序列处理回执。未知结果查询原请求；冲突保留当前输入与候选，不能重新加载旧快照。重算产生新尝试，改变提交载荷也不能沿用旧请求身份。

避免队列互相等待：队列内使用已经协调的提交入口，不重新调用会排在自身之后的公共 flush；main 等待 renderer 准备时也不持有数据库事务。正式事务只处理已准备、再次通过修订校验的短提交。

现有 [Agent 内容合同](../src/shared/contracts/agent-content.ts) 是整篇快照更新；旧消费者继续使用原来的修订检查。局部候选协议显式声明版本与能力，不能把旧整篇提交默认为安全合并，也不能只换 expectedRevisionId 重发冲突旧稿。委托允许的实时输入范围须由宿主核对，不能因接入协调而扩大交给 Agent 的内容范围。

## 历史存储与恢复接线

正式内容继续由 article revisions 承担。作品所属的任务、候选、采用和回执记录建议进入所属空间数据库，引用已有生成记录及修订；新增必要关联与状态，不复制另一套可编辑正文。现有生成过程记录、已完成结果和作品输入历史可以复用，但不等于已经保存全部未完成尝试或采用事实。新的任务必须在开始前固定依据，不能只依赖生成结束后才写入的结果记录。

renderer 的 ContentDocumentViews 只保留会话内步骤；补充检查点与有界增量日志，并由 main 负责持久化。批量写入明确已保全到的步骤范围，任务开始、候选采用、提交和安全离开等边界等待必要记录可靠保存。不能把尚在内存或写入队列中的步骤报告为可在重启后恢复；高频编辑不逐次复制完整正文。

现有 main 恢复存储位于 userData 下的 ui-state/article-editor-recovery，同一作品列举时按时间保留最近 32 份；renderer 在匹配保存确认后会清理相应检查点。当前 pendingSave 只保存 requestId、expectedRevisionId 与 contentHash。新任务不能直接依赖这套淘汰规则或请求摘要：应另存原提交完整载荷或可靠引用，纳入活跃任务、未知提交、未处理候选和撤销的依赖保护。正常恢复稿清理只释放已不再承担这些责任的记录。

修订打包保持逻辑身份，任务基准可以继续引用已打包修订；步骤日志不能仅靠修订终态重建。压缩与清理前核对引用，提交清理时再次检查新增依赖；替代记录验证成功后才释放旧记录。格式、校验或依赖读取失败保留原记录及可读候选，不沿普通无效缓存处理删除。

空间备份要核对数据库历史与候选媒体等依赖的一致性。本机 ui-state 恢复文件不会因备份数据库而自动被纳入；若承诺携带，需显式纳入备份清单与恢复协议。恢复后建立新会话并重新核验目标及权限，不自动重发旧委托。跨重启可恢复的采用记录与普通编辑器 undo stack 分别说明，旧会话栈不能直接反序列化后盲目应用。

新增存储沿现有数据库和文件服务的执行边界；文件读写、日志压缩和批量恢复使用异步、有界方式，限制读取量及在途字节，历史正文按需加载。具体容量、长期保留期限及跨重启撤销范围尚待确定；未确定前不按任意期限淘汰活跃依赖。

## 兼容与验证边界

旧记录没有任务或采用依据时保留未知，不从当前正文推导历史；新字段和关联采用可辨认的格式版本。迁移前核对现有迁移列表、发布及环境执行情况，已发布或执行的迁移不重写；同次发布遵守应用、插件与迁移各自最多升级一次的约束，文档更新本身不增加版本。

后续每阶段运行与修改相关的现有单元、组件和集成回归，执行类型检查与构建；先核对脚本实际操作。既有保存队列、迟到回执、修订竞争和恢复回归只证明原支持范围；没有直接覆盖的新合并、原生输入法、历史清理与完整转页面时序保持未验证。此方案不授权新增或改写测试、手动操作 UI 或调用模型，模拟结果不能替代实际边界的证据。

实现界面复用已有比较、候选、历史和恢复入口及 components/ui；需要的名称、状态、错误和无障碍文案同时维护英文与简体中文资源，不把任务日志或教程说明堆进日常编辑面。
