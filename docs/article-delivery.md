# 文章投递

文章投递使用持久化后台队列。提交前先保存文章，任务固定当时的版本、内容哈希、目标、投递模式、水印和图片处理选择。关闭编辑器后任务继续，应用重启恢复未完成任务。原稿、素材及其修订不因上传而改变。

折叠段落、点击揭晓与换图在普通导出和投递路径中展开为静态图文；公众号复制与浏览器伴侣交接生成专用 SVG，见[文章轻交互](article-interactions.md)。

## 选择目标与批量提交

图文的上传按钮打开目标选择窗口。勾选多个本地 API 渠道和浏览器平台后，统一提交；打开窗口、选择平台、调整图片或水印都不会发布。每个目标明确标出直接发布、上传草稿或填入浏览器。浏览器填入仍由用户在平台检查并决定是否发表。

目标选择按“本篇上次提交 → 用户保存的默认搭配 → 空选”恢复。文章记忆按资料库和文章 ID 隔离，仅在确认提交、保存完成且至少有一个目标准备就绪后写入；取消窗口不覆盖记忆。默认搭配只由“设为默认搭配”修改。已配置平台可以一次选中，也可明确选择“公众号 + 小红书”或“微博 + X”；两端均已配置时组合才可选。选组合只改勾选，不提交也不更改默认。

已停用、缺权限、未配置和已卸载的历史目标保留在窗口内，不能静默省略或替换。失效的已选目标仍可取消；未配置的有效目标可先勾选，再指定浏览器 Profile。目标状态仅在窗口打开或手动刷新时读取，本地渠道最多同时读取两个；普通编辑不触发此检查。

本地 API 渠道先按启用状态、宿主兼容性和必需权限判断是否可读取连接，再以读取到的连接状态判断是否可提交。启动快照中尚未加载的连接不能被判为缺少权限，也不能阻止窗口按需加载已保存的连接；只有连接就绪的目标进入已配置平台选择。

一次提交先等待同一个保存会话，固定确认后的文章修订和所有选项。浏览器平台共用一次正文引用展开，再按各平台准备内容；API 渠道顺序入队，浏览器目标通过现有批次交接打开。未改变的渠道路径与摘要不重复写入配置文件；入队时核对本次确认的值，另一窗口已修改时要求重新确认。

每个目标单独显示准备失败、已入队或浏览器交接结果。某个目标失败不阻止其他已准备目标。可明确重试失败的目标或重开原交接，成功目标不重复提交。入库前拒绝通过结构化回执返回；回复丢失时显示结果未确认，应先查上传记录或平台。

本地 API 请求核对实际资料库；正文引用展开、浏览器批次与重开请求携带原资料库 ID，在读取引用、记录或打开前核对，避免切库期间解析到另一资料库内的同名引用。编辑器切换文章会关闭原选择窗口，迟到的准备不会污染新文章；已经确认入队的后台任务继续处理其固定输入。

## 图片处理

本地 API 渠道菜单提供“均衡压缩”和“原图”，默认均衡。这项选择只用于接入此处理器的渠道，不影响浏览器交接。

| 输入                 | 均衡处理                                           |
| -------------------- | -------------------------------------------------- |
| 静态 JPEG、WebP      | 等比缩小，长边目标 2560，质量 0.85，不放大、不裁切 |
| 静态 PNG             | 同格式编码，保留透明，不转 JPEG                    |
| GIF、动态 WebP、APNG | 保留动画，不静默提取首帧                           |
| SVG                  | 优先复用已校验 PNG 缓存，否则经现有沙箱栅格化      |

2560 是优化目标，不是渠道硬限制；候选大小不小于原图时采用合规原图。原图模式跳过压缩，但仍执行作者选择的水印、必要的 SVG 转换与全部检查。GIF 支持已有逐帧水印；动态 WebP、APNG 与水印同时选择时明确受阻，不能丢掉动画或忽略水印。

图片压缩复用现有、无网络权限的 Chromium 沙箱，未新增原生依赖。先检查实际容器、尺寸、动画和 EXIF 方向，输出再核对 MIME、签名、尺寸与字节数；编码失败或格式回退不会伪装成成功。依据：[Canvas 编码](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas/convertToBlob)、[PNG 动画](https://www.w3.org/TR/png-3/#acTL-chunk)、[WebP 容器](https://developers.google.com/speed/webp/docs/riff_container)。[nativeImage](https://www.electronjs.org/docs/latest/api/native-image) 不处理 EXIF，不选作照片压缩器。

- 只准备正文实际引用的图片及封面，支持内联 Markdown、引用式图片和内部素材地址，忽略未使用绑定。
- 每篇最多 100 个图片素材，单张原图及最终结果均不超过 25 MiB；渠道预检限制单边 32768、总像素 100,000,000。
- 均衡另受既有解码器 16,777,216 像素上限约束，超过时明确提示改选原图或更换图片，不扩大其他图片操作的内存上限。
- 素材元数据一次查询，文件使用异步有界读取；同时最多准备、上传两张。首次失败取消其他上传，等待其结束后再开始下个任务。
- 读取后校验原始文件大小与哈希，处理后按实际上传字节重新计算哈希。同任务相同结果只发送一次；多个素材身份可共用远端对象，封面及正文引用保持原身份。
- 结果记录原图和最终图片总大小、处理和保留数量。它包括远端复用对象，不表示此次网络流量；水印、SVG 转换等必需处理可能增加文件体积。

## 投递模式和本地插件

AICanDo 保持单独安装的本地声明式插件，不进入内置清单。站点、渠道和权限由插件声明，图片处理、队列、凭据与发送前授权检查由宿主负责。

扩展宿主 API 为 0.3.10。插件通过 `configuration.deliveryMode` 选择 `PUBLISH` 或 `DRAFT`；省略时保留既有 `DRAFT` 行为。声明该字段的插件要求宿主 `^0.3.10`，这个版本独立于应用版本。

| 插件配置        | workflow                      | 请求和回执                                                                           |
| --------------- | ----------------------------- | ------------------------------------------------------------------------------------ |
| `PUBLISH`       | `articleDelivery.publish`     | 直接发布协议，正文省略 `mode`；回执可省略 `mode` 或返回 `publish`，拒绝 `draft` 回执 |
| `DRAFT`（默认） | `articleDelivery.uploadDraft` | 状态能力须包含 `draft`，正文和回执均须带 `mode: "draft"`                             |

连接检查以及每次任务开始都读取 `GET /api/integrations/aiy/status`，校验 `aiy-article-import` version 1 协议。只有草稿模式要求 `capabilities.documentModes` 包含 `draft`，发布渠道无需草稿能力。状态格式不兼容与草稿能力缺失使用不同错误码；回执模式不符、目标路径错误或跨站结果 URL 均停止。

AICanDo 插件 0.1.2 显式选择 `PUBLISH`，站点导入接口保存修订并直接发布，不接受草稿字段。幂等重放只返回旧回执，不重新发布旧版本或更新来源关联；媒体列表允许多个素材身份共用一个 key。插件源码、安装包、运行中的宿主和服务部署须分别更新。

界面根据插件模式显示“发布”或“上传草稿”。成功的新记录分别显示“已发布”或“草稿已上传”；历史回执没有明确动作时仍显示“已上传”。回执重放优先显示“已确认此前上传”，不声称重新发布。发布结果打开公开文章 URL，草稿和未标明模式的历史结果打开管理入口。站点图片上传后可通过媒体 URL 公开访问，草稿不等于私密存储。

## 保存与重试

任务表增加可空 `image_preparation_json`，保存版本 1 和 BALANCED／ORIGINAL。历史空值读作 ORIGINAL，新界面入队默认 BALANCED；重试复制原任务选择，不读取当前界面设置。现有表结构检查及升级入口负责补列，不改写文章和素材表。

可空 `delivery_mode` 列随 revision 007 升级补齐，不回写历史任务。新任务及其重试保留模式，活动任务去重也比较模式；执行前和请求前核对当前插件模式，改变后须重新发起投递。历史任务没有模式时沿用当前插件配置，因此旧 AICanDo 失败记录更新插件后可按发布模式重试。既有 `result_json` 兼容 `PUBLISH`、`DRAFT` 和没有模式的历史回执。

未新增长期成品缓存。重试按固定输入重新准备，并按实际图片和正文生成幂等键。上传链路的水印位置由固定源文件与配置确定，不因重试重新抽样；跨 Chromium 编码器升级仍不承诺字节完全一致。长期成品缓存、断点续传、超大图分块解码与全部浏览器渠道压缩不在本轮实现范围。

## 状态与失败处理

后台显示等待、准备图片、上传图片，以及按模式发布文章或提交草稿。入队、成功、失败主动通知，迟到的入队响应不覆盖新状态。工具栏状态可打开记录；当前提醒保留各文章和目标的最新结果及进行中任务，旧记录继续保存。

错误区分未关联、不可读取、格式不支持、内容改变、容器无效、文件或像素超限、转换失败及动画与水印不兼容，给出具体素材引用。新增状态和错误使用统一 i18n。

修改图片、正文或处理选择后重新上传。重试沿用旧任务修订；已发送媒体无法撤回，正文结果未知时先检查远端文章，不能靠再次发布补回执。

切换资料库或正常退出时，先停止该库接受新上传并中断本地等待，再等待库操作结束。后台任务与兼容直传接口共用各自资料库的上传生命周期；连接读取、状态请求、图片处理与上传、正文提交都接收取消信号。并发图片处理在释放任务前排空，切库失败恢复时只重新启动此前已启动的队列。

被本地中断的后台任务保留原修订和目标，记录 `DELIVERY_INTERRUPTED`，需先检查目标平台再手动重试；未开始的任务仍排队。已经收到并校验成功回执的任务保持成功。中断不能撤销已经送达远端的媒体或正文，也不能据此声称远端已取消。独立的连接保存和测试保留原有 15 秒请求超时。
