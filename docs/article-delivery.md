# 文章投递

文章投递使用持久化后台队列。提交前先保存文章，任务固定使用提交时的文章版本、内容哈希和投递目标。关闭文章编辑器后，任务仍可继续；应用重新启动时恢复未完成任务。

## 图片处理

- 只读取正文实际引用的图片和封面，忽略编辑过程中遗留的未使用素材绑定。
- 支持内联 Markdown 图片、引用式图片和内部素材地址；正文与封面复用同一素材时只上传一次。
- PNG、JPEG、WebP、GIF 保留原格式。SVG 优先使用经过校验的 PNG 缓存；缓存不存在或无效时，通过现有沙箱解码器转换，不修改原始素材。
- 每篇最多投递 100 张图片，单张原图和转换结果均不得超过 25 MB。素材元数据一次查询，文件检查使用异步 I/O。
- 同时最多准备、上传两张图片。首次失败会取消其他上传并等待其结束，再开始下一个文章任务。
- 原始图片读取后校验大小与内容哈希；文章和图片分别使用内容派生的幂等标识，重试可复用已上传图片。

## 状态与失败处理

顶部后台任务显示等待、准备图片、上传图片进度和发布阶段。进入队列、成功和失败会主动通知；失败不会被迟到的入队响应覆盖。

文章工具栏保留可点击的投递状态提示，点击可查看投递记录。后台任务按文章和目标保留最新结果，另保留仍在进行中的任务；旧失败在重新投递后从当前提醒中移除，历史记录继续保留。

图片错误区分未关联、不可读取、格式不支持、超限、内容变化和 SVG 转换失败，并显示对应素材引用。后台任务和历史记录都提供重试入口。

重试使用原任务的文章版本。修改图片或正文后，需要重新投递，才能使用修改后的内容。
