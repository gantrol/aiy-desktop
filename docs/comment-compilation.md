# 将选定评论整理成新稿

本功能在主工作区的文章／大纲评论面板中提供“选择评论 → 整理成文”。复用现有文章编辑、保存、来源链接与打开到旁边的导航；不是把原评论转换类型，也不自动调用 AI、同步正文或发布到平台。

## 使用路径

选择若干评论后，可以跨评论状态筛选继续选择。在确认面中修改新稿标题，调整评论顺序，移除本次不需要的评论，选择是否带上已有的标注摘录，再选择创建图文稿或大纲。原评论、回复、处理状态和原稿均不修改。

关闭确认面后增删评论选择，会重新读取评论快照，但保留已填写的标题、输出格式和摘录开关。仍选中的评论沿用已调整的相对顺序，新选评论追加到末尾；明确清空选择才重置这些设置。

新稿默认放在原稿所在图集。图文按所选顺序建立章节，大纲按同样顺序建立条目；评论正文和可选摘录保留为普通可编辑文字，沿用现有纯文本入文档转换，不将评论字符串解释成 HTML、图片或可执行引用。未选中的回复、附件和整段原文不隐式复制。

采用的是已保存内容。每次首次准备或明确刷新，先通过编辑会话保存原稿，再调用带空间及文章身份的 `articleOpen` 读取实际来源；不以会话缓存代替重新读取。评论可能独立修改而没有新的文章修订。刷新保留用户输入的标题、顺序、输出格式和摘录选择，重新核对每个评论身份。所选评论已删除时保留选集并报错，由用户移出，不悄悄丢弃。

确认面固定来源修订和最新评论快照。确认后主进程再次核对，内容变化时拒绝创建并要求刷新。读取期间切换来源或重新装载编辑会话，不采用旧响应；刷新不覆盖正在编辑的原稿。

## 数据和来源

`comment-compilation-create` 属于已有 `content-library:command` 入口；renderer、preload、主进程使用同一输入合同。一次最多 50 条评论，正文与选用摘录合计不超过 200,000 字符、5,000 行。主进程只复制自己读取的已保存评论；客户端正文仅作比较依据。

新稿、首个修订、创作项登记与来源记录在同一数据库事务中写入。首次写入记为 `COPIED`，不是 AI 生成。正文保留已有署名；未有署名的评论不编造姓名。来源链接放入现有作者／写入详情，不强行插入文章正文，避免将本地地址带到平台稿中。

来源细节进入现有 `article_revision_context.context_json` 的可选 `commentCompilation` 字段。记录来源文章、采用修订、评论 ID、评论创建修订及时间、原位置、署名快照，以及新稿首个修订中的正文／摘录块 ID。原评论可独立继续修改；新稿不会跟随覆盖。复用原文章修订历史保留首次复制的文字，不在每个保存上下文中重复存整段正文。后续普通修改保留这份首次来源记录。

返回值同时包含保存后的文章及其创作项。结果合同单独维护，避免来源元数据与文章／作者合同产生运行时循环依赖。没有新增数据库迁移、业务保存层、应用版本或插件版本。

## 重试与导航

请求以 UUID 加完整已校验输入摘要生成新稿身份。相同请求重试先核对既有新稿，再决定是否写入；已经创建后即使新稿被继续编辑，也返回同一身份及当前登记，不用新一次保存覆盖它。复用请求 ID 但改变输入会拒绝，已删除结果不会复活。

编辑会话内共用一个选择和提交状态，左右分屏不重复提交；每次确认面只有一个面板拥有。未知 IPC 结果保留原请求供重试，不能边修改输入边复用原请求。关闭确认面不宣称取消可能已经完成的写入。

保存后先通过 `article-created` 事件把文章与创作项分别并入当前空间的列表，再尝试导航。这与大纲“转为页面”共用同一登记通知，不新增平行列表。即使导航失败、来源页关闭或文章投影已更新，仍登记创作项；旧空间返回不修改当前空间。较新的文章或创作项投影不被旧结果覆盖。

保存与打开分别判断。使用准确文章 ID 打开到旁边；原页已离开、被隐藏或保存未完成时不抢走当前工作面。无法打开时保留“打开新稿”，不再创建第二篇。

本版不持久化应用重启前的未提交选集。应用退出后，原评论始终保留；已经确认写入的新稿通过原有创作库和文章恢复机制继续。跨文章选集、选择回复、AI 综合写作与主流平台交付没有在此 PR 中实现。
