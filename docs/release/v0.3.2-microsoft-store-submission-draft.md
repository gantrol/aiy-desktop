The Store version is deliberately different from the app semantic version. Microsoft requires the first field of a Windows 10/11 package version to be non-zero and the fourth field to be zero. The proposed deterministic mapping is:

- app `0.3.2` -> Store `1.3.2.0`;
- app `0.3.3` -> Store `1.3.3.0`;
- app `1.0.0` -> Store `2.0.0.0`.

Do not upload the current `AIYImageTools.Dev` test package. Its identity, publisher, certificate, data root, and purpose are different from the reserved Store product.

## 2. Package preparation

Use `npm run make:store` for a packaging dry run. Use `npm run release:store` for the gated final build; it stops on lint, type, or test failures before replacing the submission artifact.

1. Generate the production manifest using the exact case-sensitive identity values in section 1.
2. Set the Store package version to `1.3.2.0`; keep `package.json` at `0.3.2`.
3. Target `Windows.Desktop` x64 only for this first submission.
4. Declare only capabilities that the packaged app actually uses. Electron desktop execution requires `runFullTrust`; explain it in Submission options.
5. Package only public application code, built-in lightweight starter resources, licensed icons, and required runtimes. Do not package external production content libraries.
6. Prefer a deterministic output name such as `AIY-0.3.2-store-x64.msix`.
7. Inspect the final `AppxManifest.xml`, package file list, identity, publisher, version, architecture, and declared capabilities before upload.
8. Run WACK from an elevated terminal in the active signed-in Windows session:

   ```powershell
   appcert.exe reset
   appcert.exe test -appxpackagepath "D:\path\to\AIY-0.3.2-store-x64.msix" -reportoutputpath "D:\path\to\AIY-0.3.2-wack.xml"
   ```

9. Keep the final MSIX, SHA-256 digest, WACK report, manifest snapshot, and build log together as release evidence.

AIY helps you DIY with AI. It is a local-first desktop workspace for AI image generation, video-to-article workflows, and creative asset management.

You can:

- organize prompt revisions, references, and generated results by creative project;
- compare models, settings, and prompt revisions side by side and inspect their differences;

- organize video content with transcripts, notes, and article workflows; and
- import, export, and migrate complete local spaces.

## 6. Certification text drafts

### 6.1 `runFullTrust` justification

> AIY is an Electron desktop application. The `runFullTrust` capability is required to launch its packaged Win32 executable and to perform user-initiated local file operations, SQLite database access, media processing, and optional local runtime or command-line integrations. The app runs at the current user's standard integrity level. It does not request administrator privileges, install drivers or services, modify system policy, or access other users' data.

### 6.2 Generative-AI disclosure

> AIY provides live generative-AI workflows through model services selected and configured by the user. Prompts and user-selected reference media are transmitted only when the user initiates the corresponding request. Outputs are shown to the user for review; AIY does not automatically publish generated content or operate a public content feed. Provider-side moderation responses are surfaced as structured failures. Users can report inappropriate generated content through `TODO: exact in-app route and private contact method`.

Do not submit this paragraph until the `TODO` report route exists and has been verified in the release build.

### 6.3 Notes for certification

> AIY is a local-first Electron desktop application for organizing AI-assisted creative work. No AIY account or sign-in is required.
>
> Core local-space creation, browsing, dictionary, gallery, comparison, import, and export features work without an AI provider. Live AI generation and assistant features require the tester to configure their own supported provider credentials or an authenticated local runtime; no provider credentials are bundled.
>
> The app sends only the prompt and reference media explicitly selected for a user-initiated request to the configured provider. Other local-space contents are not uploaded merely because a provider is configured.
>
> Suggested certification path:
> 1. Launch AIY and create a new local space.
> 2. Open the starter dictionary and gallery content included with the application.
> 3. Create a local project, add a prompt and local reference image, and inspect its history.
> 4. Open comparison mode and compare two local result records.
> 5. Export the local space to an archive.
> 6. Create or select a separate empty location and import the exported archive.
> 7. Confirm prompts, media, dictionaries, albums, and source relationships are restored.
>
> Optional AI-provider paths require tester-supplied credentials. The application never requires elevation and installs no driver or Windows service.

Before submission, replace the generic path above with exact release UI labels and state whether starter content is included automatically or must be imported through the content-pack UI.
