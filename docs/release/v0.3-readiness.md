## 发布边界

- v0.3.0 已确定为产品运行时、IPC、新建资料库和发布资源的第一次正式发布 baseline；只有该版本真实发布后，这一兼容合同和不可变边界才成立。
- 当前候选版本语义分为三层：产品与已完成应用级验证的内置扩展使用 `0.3.0`；首发内容包与尚未完成真实 API 验证的扩展使用 `0.1.0`；manifest、数据库、IPC、worker、缓存、请求快照和本地偏好等内部协议从整数 `1` / `v1` 起步。发布前仍可随最终实现重整。
- 当前候选的词典、词盘与 fixture 内容格式统一为 `0.3.0`，不保留 `v0.4` 文件名、schema 或 pre-release revision 2+ 修补分支。业务对象自身的不可变修订号、Prompt 版本号、第三方依赖版本与外部 API／模型版本不属于此版本基线。
- 本次发布不包含 AIDoList 默认入口、WorkDraft、AIDoItem 或 DelegationSnapshot；当前创作入口继续使用现有 Creator 与 CreationDraft／PromptDraft，AIDoList 设计移至后续 P1。
- 空资料库只装载 `v03-baseline.sql`，写入 `product_data_baseline=0.3.0` 与 `database_schema_revision=1`。
- 首发候选代码不包含任何预发布编号迁移、旧库接管器或迁移修复器；发布前的最终表、索引和触发器继续合并进单一 baseline。
- 旧开发库和其他预发布 schema 不进入兼容范围，保持原样并明确拒绝，不在启动时删除、重建或猜测迁移。`0.3.0` 正式发布时冻结 `v03-baseline.sql`；此后只新增 forward-only migration，并且不修改任何已经随正式版本发布的迁移。
- 已注册的当前空间若数据库文件缺失，必须报告数据不可用且零写入；不得把文件丢失当作空库并静默创建替代数据库。这是当前数据安全要求，不是旧库兼容。

### 首个对外版本范围

- 本候选用于交付首个可运行、可交互的对外版本，不声称已经完成 `tools/docs/v0.3/05-core-requirements-and-acceptance.md` 的全部长期 P0/P1 规划。
- 预发布主链路固定为：启动／恢复本地空间 → 输入目标与参考 → 选择生图模型 → 生成或编辑 → 查看真实任务状态 → 保留、重试、比较或导入结果 → 在词典与素材视图继续整理。
- 上线前必须守住四个机制：首启与重启可用；生成失败不污染成功结果且可重试；后台任务与退出状态真实；启动错误至多报告一次，图标或可选资源缺失不能触发阻塞弹窗循环。
- AIDoList、完整 Agent、旧库迁移、包发布／撤回、网站同步、批量评测和更多模型角色继续延期，不阻塞首个对外版本。
- 尚未完成真实 API 验证、版本仍为 `0.1.0` 的可选供应商扩展不进入 `0.3.0` 首发承诺，也不作为本次发布阻断项。

## 已完成

### 产品与发布资源

- 包版本、产品身份、协议、环境变量、用户数据目录和可执行文件统一到 AIY / `0.3.0`。
- builder 的额外资源只包含 `extensions`、`content-packs`、`configuration` 与应用图标，不打包 `tools`、demo 或历史 release 目录。
- 当前本机解析到的额外资源为 16 个文件、约 1.03 MiB；9 个 JSON 均已解析校验，creation starter 的 4 张图片均有包内引用。
- `content-packs/creation-starter` 已从本机 junction 实体化为普通仓库目录；4 张 WebP 已通过精确 `.gitignore` 例外纳入版本控制，fixture 的 hash、MIME、尺寸与字节数已和实际文件对齐，原始外部目录保留不动。
- 未打包约 3.4 GiB 的 common-term 示例集；已有资料库中已导入的数据保留，新 v0.3 空间不再预装该样例集。

### 数据基线

- 单一 baseline 直接包含 Album、Pack、文件投影、Prompt 快照、标注、创作输入暂存、词盘 Prompt 内容节点与内联拼接模式等最终结构。
- Pack 使用单一稳定 ID；标注只允许 `RECTANGLE / BRUSH`；词盘只保留当前 v0.3 revision 结构。
- 初始化只区分“明确创建的新空库”和“当前候选 baseline 库”；任何旧开发库、预发布近似结构或已注册但数据库文件缺失的空间都保持零写入并明确拒绝。

### 运行时收敛

- Prompt 仅接受 `COMPOSED / FLAT_INPUT`，历史推荐、知识蒸馏、关系查询和生成执行均要求规范冻结快照。
- 生成入口统一为 prepare → freeze → execute；删除直接 generate 和旧 worker/renderer 协议分支。
- renderer、preload 与 IPC 只保留 `local-spaces:*`；删除 `libraries:*`、旧 Gallery/Album DTO 别名和旧 localStorage 转换。
- 删除旧文件投影扫描器、all-materials 物理投影、旧 Tree 几何/预览、masonry 与中文 locale 兼容导出。
- 标注运行时仅支持 `RECTANGLE / BRUSH`；助手结果仅从 proposal 读取；词盘仅从 revision 读取。
- 内置 fixture 只接受 `schemaVersion=0.3.0`，不再为缺失版本写入 `0.1` 回退标记。
- 默认空间现在显式注册真人肖像内容包，避免“已导入词条但没有 Pack 身份”的孤立状态。

### 结构性清理

- `database.ts` 继续作为薄 facade；baseline 初始化、快照解析、binding 规范化和输入暂存进入独立模块。
- Local Space / Pack 合同拆到 `src/shared/contracts/`，存储类 IPC 拆到 `src/main/ipc/storage-handlers.ts`。
- 生产代码扫描未发现 `TODO/FIXME/HACK` 或 `as any`，但这不代表类型边界安全。2026-08-06 复审已经确认 provider response 的直接 assertion、全可选 `unknown` interface 和伪泛型 parser；完整范围见本页“代码审计复审”。

## 代码审计复审

2026-08-06 的完整 finding、证据、整改批次和验收口径见
[`../v0.3.0/alpha/code-smell-audit-and-remediation-2026-08-06.md`](../v0.3.0/alpha/code-smell-audit-and-remediation-2026-08-06.md)。整改已经分批进入生产代码和门禁；每个主题的已完成、部分完成与未完成状态以该文档的实施状态表为准。

首发候选当前至少受以下结论约束：

1. 已注册数据库缺失时禁止静默创建空库；异步工作必须固定一个 LibraryContext，并在切换／退出前 drain。
2. DeepSeek 和其他 provider 响应必须从 `unknown` 经 runtime schema 解码，不能用 `response.json() as T`、全可选 `unknown` interface 或不带 decoder 的泛型 parser。
3. assistant cancel／worker timeout 必须端到端取消或返回“状态未知”，不能让付费任务继续执行并迟到写库。
4. 分类 move／restore／merge 必须保持完整 revision、facet assignment、context profile、change event 和 tombstone 语义。
5. i18n 写入使用精确 locale；用户文案来自 catalog；provider／main 错误以结构化 code/params 交给 renderer 本地化。
6. 异步化不证明批量 I/O 合理。无消费者工作直接删除，必要任务才使用测量、增量化、有界并发、取消和背压。
7. Tiptap lifecycle `flushSync` 警告、异步 stale state、媒体 resolver／decoder 权限和当前质量门禁必须在首发判定中保持可见。
