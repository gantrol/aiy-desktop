# 设置叠层

应用菜单及个人菜单通过 `App.changeView('settings')` 打开 `SettingsDialog`。设置状态属于应用壳层，不创建或替换工作区标签；原有工作区保持挂载。使用已有 Dialog 的模态隔离、Esc 与外部点击关闭，退出时恢复入口焦点。

`SettingsScreen` 负责所选部位及本次已访问的设置区，`SettingsLayout` 负责可点选的工作区示意。设置区首次访问才挂载，切换时隐藏已访问区以保留未保存的权限选择。现有字体、语言、关联、维护和权限组件继续负责各自的状态与保存。字体组件按传入角色显示和重置，界面与正文／代码的重置范围分开。

内容管理与模型分配沿现有导航入口打开新工作区标签，并退出设置叠层；来源工作区保留。已经保存的旧 `settings` 导航目标仍可解析，激活时打开相同叠层；退出旧目标时优先返回历史，没有历史则替换为创作入口。保留这一分支用于已发布的工作区存储格式，不再生成新的设置标签。

没有增加尺寸调整、存储字段、数据库迁移或 IPC。字号、栏宽／区域高度及整体缩放另行设计。

验证使用现有工作区快捷键、设置与内容管理、语言启动、权限信息和内容生命周期测试，以及类型检查、lint、格式检查和生产构建。新增叠层的布局、跨菜单焦点和窄窗口视觉仍需实际使用核对；没有执行 UI 手动验收。详细执行记录留在私有测试仓。
