# 一次玫瑰创作分享：从灵感到再用

- J-01：用一篇图文记录一次玫瑰创作，配一张封面，为下次留下方法
  - 这是一份可修改的教学起稿，所有结果尚待你实际完成
  - 媒体、封面撤销、版本选择和外部交接按所用版本支持范围演练；没有入口的条目标为待验证，不算失败或已完成
  - 不需要模型或发布账号也能开始：手写正文，使用自己的材料，先导出到本地
  - 只想试大纲时停在保存与重开；不必填完全部分支
- 灵感：先记下来
  - 我想说明：这次怎样从参考走到满意结果
  - 新建后连续写两段中文，再立即切到另一份内容，然后回来核对
  - 保存后离开，再打开，应看到同一份正文；不用等一个内部错误消失才继续
  - 想放在桌面时贴出原内容，回到主窗口继续写，不另存一个便签副本
- 调研：留下支持与反例
  - 添加自己选定的参考和出处；没有读取过的资料标为待核对
  - 支持的做法：填写观察与理由
  - 不合适的做法：填写反例和适用限制
  - 决定：选一个足够小的制作尝试，也可以暂缓
  - 导航用链接；实际采用的文字或媒体按引用规则保留当时依据
- 组织：一份总纲，多份成果
  - 文章：想解释什么，怎样分段，哪些内容还缺依据
  - 封面：选自己的图片，记录希望读者第一眼看见什么
  - 短帖：需要独立改写时另建作品，从这里添加返回链接
  - 试折叠一支、移动条目，再展开；内容仍完整，链接仍指向原对象
  - 这里的子条目仍是大纲正文，另建作品才产生独立内容
- 创作与修改：采用准确的结果
  - 先写一段正文，再从所选材料配图
  - 可手动采用已有图片；使用 AI 时只提交这次选定的输入和依据
  - 候选 A：尚未生成或添加
  - 候选 B：尚未生成或添加
  - 采用后回到原位置，检查图片和正文一起保存
  - 再替换一次封面并撤销，检查恢复的是本次替换前的选择
  - 制作期间若已继续改稿，先比较旧候选，不能直接覆盖新稿
- 发布与交付：知道交出了哪版
  - 先保存，记录本次使用的修订、目标和动作；若版本尚无历史修订选择入口，就从当前已保存稿演练
  - 本地导出：记录实际文件及对应修订；没有导出就保持待完成
  - 平台交接：有真实账号和授权时再做，记录是上传、填入还是已发表
  - 多目标中一项失败，保留成功结果，只继续失败项
  - 结果未知时先核对；不要通过重新点击制造重复发表
  - 交付后改一句正文，旧交付仍属于旧修订
- 积累：下次能接着做
  - 关闭后重新查找这次作品，回到材料、采用理由和交付记录
  - 只把实际有效的方法另存词条或配方；保留适用条件
  - 基于旧成果另做一稿，写入新内容，检查旧稿仍可找到
  - 缺模型或停用插件时，已保存文字、图片和来源仍可查看
  - 留一条真实反馈：哪一步重复劳动最多，下次只改这个阻碍
- 其他起点：按需要展开，不必把同一套操作再走一遍
  - J-02：从已有词条或配方开始
    - 选修订和参考，调整本次输入；取消选择不改原方法
    - 想长期复用本次改动时明确另存
  - J-03：从自己的视频资料开始
    - 回听、校对、选段或选帧，在当前支持范围保存与导出
    - 重新转写不能覆盖已校对内容；来源缺失仍保留已有文字
  - J-04：用 AIY 管理一次 AIY 修复
    - 原反馈：新创作正常输入出现 EDITOR_INPUT_UNSETTLED
    - 区分观察、原因猜测和已验证解释，记录适用版本
    - 选定需求与证据交给 Codex，带回实际修改与未完成项
    - 测试记录实际代码和测试版本；未运行、失败、重试通过分别写明
    - 软件发行记录实际安装包及后续结果，不从 PR 合并推断已安装
    - 把本次故障保留为回归案例，再决定是否需要自动化下一步
