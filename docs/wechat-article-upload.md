# 公众号文章图片上传

公众号文章沿用整篇富文本粘贴的输入方式：在原稿位置内嵌图片数据，一次交给微信编辑器，由微信处理上传。正文不生成图片占位文本，也不通过逐张移动选区、删除文本和粘贴文件来上传。

`browser-companion/src/lib/composer-adapters/wechat-article-media.ts` 把已经校验的交接文件异步转换成 data URL，再嵌入离线 HTML 模板。它不解析页面登录参数，不自行调用微信图片接口。正文继续由 `wechat-article.ts` 通过宿主粘贴事务写入；宿主未接受粘贴时停止，不能用直接修改 DOM 冒充图片已进入上传流程。

图片按素材索引去重读取，同一时刻只编码一个文件，同图的多个位置复用编码结果。单张至多 32 MiB，正文图片原始总量至多 96 MiB，含重复位置的 HTML 至多 132 MiB；整篇限额与已有公众号剪贴板路径一致。在分配 base64 字符串前计算重复位置的预计大小，超限时不写正文。准备期间正文变化或离开页面时停止。

粘贴后最多等待 10 秒，让宿主完成正文异步检查与文档事务。随后确认图片数量、图文次序、有效的微信文件标识、HTTPS CDN 地址和图片加载状态；仅出现 data URL、blob URL 或本地预览不能算上传成功。图片等待总量最多 8 分钟，连续 90 秒没有新增加载完成的图片则失败；网站报错或用户继续输入时停止本次确认，不自动再粘贴或重传。微信已经接收的上传由网站继续管理，停止本地等待不等于撤销远端请求。

普通文章只提交一次完整正文。含交互 SVG 的文章先提交完整静态图文，上传确认后复用微信图片地址，再提交整篇交互版本；节点或动画未保留时恢复静态版本并报告失败，用户已继续编辑时不覆盖其修改。封面继续使用既有上传与裁切流程。通用交接层不要求文章文件输入控件已挂载。

失败时保留网页中已填入的图文供用户处理，交接不标为完成；不会遗留 AIY 图片占位文字。真实网页的持久文档、图片内容与次序、封面和回执仍须对应账号验收，类型检查及构建通过不能替代该验证。
