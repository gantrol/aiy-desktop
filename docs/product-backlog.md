# 产品后续需求

## 已实现首版：Codex 通过 AIY CLI 创建贴图

状态：0.3.7 已实现本地 CLI、版本化 JSON 契约、仓库级 Codex Skill 和微博命令动作；暂不实现 MCP、Codex 插件或公开上架。首版 CLI 连接当前图库已有的后台 worker，因此 AIY 需处于打开状态，或后台 worker 尚未退出。

目标：用户在本地 Codex 中描述贴图需求并提供参考资产，Codex 按 Skill 指引调用 AIY CLI；AIY 负责冻结输入、启动生成、持久化任务并返回稳定的资产结果。CLI 契约后续可由 MCP 适配器复用，但首版不以 MCP 为前置条件。

首版实现：

- CLI 使用版本化 JSON 输入输出；标准输出只写机器可读结果，诊断写标准错误，并为不可用能力、无效输入、冲突、取消和生成失败提供稳定错误码。
- 能力查询、参考资产导入、贴图草稿准备、生成启动、任务查询和取消保持为独立命令。有耗时或额度消耗的生成命令快速返回 `jobId`，不让 Codex 长时间占用一个命令调用。
- `action send-weibo` 只读取已完成任务记录的不可变输出，通过现有浏览器伴侣暂存正文与图片并打开微博；不接收任意附件路径，不使用桌面控制，也不点击最终发布。
- 每次异步操作捕获一个不可变图库上下文。CLI 不直接访问 renderer 或另开 SQLite，不绕过现有生成服务、事务、素材校验和来源记录。
- Skill 只负责识别意图、整理贴图规格和编排命令；模型路线、质量、数量、参考图上限和可用状态均由 CLI 实时返回，不硬编码价格或能力。

图片附件契约：

- 严格区分“Codex 能看见的聊天图片”与“AIY CLI 能读取的文件”。粘贴、截图或聊天附件可能只有模型可见内容，不能据此猜测文件名、临时目录或可复用路径。
- CLI 只接收显式 AIY `assetId` 或显式本地文件路径。若附件没有可验证的本地路径，Skill 必须请用户提供原文件路径或先在 AIY 中导入，不得把视觉上下文伪装成已经传给 AIY 的文件。
- 多张图片使用数组或可重复参数逐项传递，不使用逗号拼接路径；每项保留顺序和用途，例如主体、风格、构图或编辑源。
- 本地文件必须是明确的普通文件。AIY 在使用前校验规范绝对路径、大小、真实媒体签名、容器完整性和尺寸；PNG 还校验 CRC、解压及栅格长度，JPEG/WebP 的统一沙箱解码是后续硬化项。验证后在生成开始前复制为任务持有的不可变输入，不得依赖 Codex 会话临时附件继续存在。
- 不接受目录、通配符或未经单独设计的远程 URL。成功导入后返回稳定 `assetId`、内容哈希和媒体元数据，后续命令优先使用 `assetId`，不继续传递原始路径。
- Skill 在调用生成前复述每张参考图的来源和用途；无法确定图片与路径的对应关系时停止，不凭附件顺序猜测。

实现入口：`docs/agent-cli.md`、`.agents/skills/aiy-cli/` 和 `node out/main/agent-cli.js <command>`。后续待办是安装包内的独立命令分发、跨仓库 Skill 分发，以及验证需求稳定后再决定是否增加 MCP 适配层。

验收场景至少覆盖：单张路径附件、多张带角色附件、AIY 既有 `assetId`、文件名含空格或逗号、聊天中可见但没有本地路径的图片、附件在任务启动前被移动，以及同一生成命令的安全重试。

## 低优先级：图库品牌配图与关联关系

状态：仅记录，当前不实现。

图库可考虑拥有自己的切换配图。后续设计前需先确定：

- 配图归图库所有，还是引用图库内的一项素材；其删除、替换和缺失状态如何处理。
- 源图库商标、目标图库商标和图库配图如何随切换事件一起提供。
- 配图缺失时只按现有商标动画运行，不为组合差异增加兼容分支。

建议按可用资产自动选择动画编排：

| 可用资产               | 动画编排                            |
| ---------------------- | ----------------------------------- |
| 源商标、配图、目标商标 | 商标 1 → 配图 → 商标 2              |
| 源商标、配图           | 商标 1 → 配图，并由配图衔接目标界面 |
| 配图、目标商标         | 配图先展开 → 商标 2 落位 → 目标界面 |

交互原则：编排跟随真实切换进度，不为完整播放动画增加等待时间。
