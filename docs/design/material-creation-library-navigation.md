# 素材页：素材与创作关系设计

状态：已确认，进入实现
日期：2026-08-05

## 1. 问题与结论

当前实现把素材页拆成“素材 / 创作 / 词典”三个一级分类，同时把创作图集投影压平成了普通列表。这同时破坏了两项已经确认的产品约束：

1. 词典相对独立，只与素材并列为一级 Tab。
2. 创作与素材有交融关系，创作应当是素材树中的固定只读投影，并保留创作页的真实树层级。

最终信息架构只有两个一级 Tab：

- **素材**：全部素材、固定“创作”投影、用户素材图集树、已归档素材图集。
- **词典**：沿用词典自己的只读查询树。

“创作”不是第三个 Tab，也不是数据库里可改名、移动或删除的普通素材图集。

## 2. 素材侧栏结构

```text
素材
├─ 全部素材                         固定入口
├─ 创作                             固定、置顶、不可变、只读
│  ├─ 创作图集 A                    镜像创作页层级
│  │  ├─ 子图集 A-1
│  │  │  └─ 创作条目 1
│  │  └─ 创作条目 2
│  └─ 未归图集                      固定虚拟分组
│     └─ 创作条目 3
├─ 我的素材图集                     用户可写树
│  └─ ……
└─ 已归档                           仅在存在归档项时显示

词典
└─ 词典查询树
```

所有图集分支复用现有树状视觉与交互：缩略图堆叠、紫色连接轨、展开/收起和层级缩进。侧栏不显示数量，数量只出现在内容区标题。

### 节点权限

| 节点         | 来源                     | 素材页权限                   | 跟随上游变化              |
| ------------ | ------------------------ | ---------------------------- | ------------------------- |
| 全部素材     | 固定查询                 | 只读                         | 自动                      |
| 创作         | 固定查询根               | 只读、不可改名/移动/删除     | 自动                      |
| 创作图集     | 创作页图集投影           | 只读                         | 创作页改名/移动后自动更新 |
| 创作条目     | Prompt Series 投影       | 只读                         | 创作页移动/删除后自动更新 |
| 未归图集     | 无创作图集成员关系的创作 | 只读                         | 自动                      |
| 用户素材图集 | Material Album           | 新建、改名、移动、删除、收集 | 不受创作树移动影响        |
| 词典节点     | 词典分类与词条查询       | 只读查询                     | 自动                      |

## 3. 图片身份与关系

图片本体使用稳定的 `ImageAsset` 身份；进入素材库后拥有 `Material` 身份。图集、创作和词典都只保存关系，不复制图片本体。

同一张图片可以同时是：

- 创作 A 的产出；
- 创作 B 某个版本的输入或编辑源图；
- 一个或多个用户素材图集的成员；
- 词典词条的示例图。

这些关系互相叠加，不能用单一 `source` 字段相互覆盖，也不能因移动到素材图集就从“创作”投影中消失。

### 创作输入分类

| 输入场景                 | 数据身份                             | 素材页“创作”投影   | 关系         |
| ------------------------ | ------------------------------------ | ------------------ | ------------ |
| 从素材库选择             | `ImageAsset + Material`              | 显示               | `INPUT`      |
| 上传并选择“保存到素材”   | `ImageAsset + Material`              | 显示               | `INPUT`      |
| 上传并选择“仅本次创作”   | 仅 `ImageAsset`                      | 不显示             | 版本私有输入 |
| 基于图片编辑             | 依原图是否有 `Material` 决定是否显示 | 有 Material 时显示 | `SOURCE`     |
| 蒙版、控制图、临时中间件 | 内部工件                             | 不显示             | 内部关系     |

输入关系绑定到具体 `PromptVersion`。内容区默认按当前版本解释“输入”；历史版本仍保留可追溯关系，但不会把旧输入混进当前结果。

### 创作产出

成功且可见的生成结果、导入产出和本地变换产出都属于 `OUTPUT`。产出进入“全部素材”，并出现在固定“创作”投影中；它不会自动创建同名用户素材图集。

把产出加入用户素材图集是新增成员关系（复制式收集语义），不改变创作归属。

## 4. 内容区交互

选择“创作”、创作图集、未归图集或具体创作条目后，内容区顶部显示：

- **全部关联**：该范围内已经具有 Material 身份的输入、源图与产出，按图片去重；
- **输入**：`INPUT` 与 `SOURCE`；
- **产出**：`OUTPUT`。

不把“输入 / 产出”继续做成侧栏子节点，避免树层级被关系维度污染。同一图片同时命中输入和产出时只显示一张卡片，但保留多个关系标签。

选择普通素材图集或“全部素材”时，继续使用素材来源筛选；选择词典时继续使用词典自己的范围筛选。

内容区标题显示当前节点名称、路径和结果数量。创作投影中的管理操作只提供“打开创作”；改名、移动、删除必须回到创作页完成。

## 5. 生命周期规则

### 改名与移动

- 创作图集或创作条目在创作页改名、移动后，素材页虚拟树同步变化。
- 用户素材图集成员关系不受影响。
- 素材图集改名、移动不影响创作树。

### 删除创作

- **保留产出**：先保证产出拥有 Material 身份，再删除创作关系；图片仍留在全部素材和用户素材图集中，但不再出现在“创作”投影。
- **移入废纸篓**：只有没有被其他创作、素材图集、收藏、词典或其他业务关系引用的产出才可随创作删除；有外部引用的图片必须保留或要求用户明确处理引用。
- 输入素材永远不能因为删除某个创作而被删除。

## 6. 数据投影与性能约束

素材页继续只调用现有 `materialAlbumsList` 首屏请求。这个返回值一次性包含：

- 固定创作根；
- 保留真实父子关系的创作图集节点；
- 创作条目叶节点与未归图集节点；
- 用户素材图集；
- 词典查询所需的既有数据。

计数和预览使用集合查询批量汇总，不允许渲染映射中逐项访问 SQL/文件系统，也不新增每节点 IPC。分页图库查询通过“选中虚拟节点 + 关系筛选”组合完成。

本方案不新增持久化的“创作素材图集”，因此不需要把虚拟节点写入 `albums`，也不重写历史迁移。

## 7. 验收标准

- 素材页顶部只有“素材 / 词典”两个 Tab。
- 素材 Tab 内“全部素材”之后固定显示不可变的“创作”树。
- 创作图集层级与创作页一致，未归属的创作位于“未归图集”。
- 普通素材图集仍可独立存在，即使没有任何创作，也不会出现在创作页。
- 侧栏所有图集分支使用树状视觉且不显示数量。
- 选中创作范围后可在“全部关联 / 输入 / 产出”之间切换；输入/产出不是侧栏节点。
- 私有输入不出现在素材页；已有 Material 身份的输入可以出现。
- 将创作图片收集到素材图集不会改变其创作归属。
- 创作树移动、改名自动反映；素材图集成员关系保持不变。
- 没有新增首屏 IPC、逐项 SQL 或同步文件访问。
