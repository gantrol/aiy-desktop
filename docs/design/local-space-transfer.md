# 本地空间迁移与传输

## 产品边界

本地空间迁移、空间导出/导入和内容包是三个不同能力：

- 旧版迁移从本机已知的旧注册表发现空间，在用户确认后复制或原地注册。
- 空间导出/导入用于用户主动备份、换机和交付自己的完整资料。
- 内容包只承载可分发的规范内容，不包含用户数据库、创作历史、账号配置或生产内容的隐式同步。

任何一种能力都不能在应用启动时自动导入或覆盖用户数据。

## 已落地的迁移事务

Store 版使用独立 userData，并把旧 `%APPDATA%\AIY` 及 `AIYImageTools.Dev` 包内的历史预览目录作为只读发现源。迁移事务遵循：

1. 从有界、运行时校验过的旧注册表和 `library.json` 发现候选；renderer 只接收不含路径的候选 ID。
2. 要求旧数据库已干净关闭，并校验 schema revision、`quick_check` 和数据库摘要。
3. AppData 内的旧空间复制到用户选择的持久目录；外部空间可以原地注册。
4. 复制采用有界并发和流式 I/O，保留有效硬链接，拒绝符号链接、非空 WAL、超限空间和复制期间变化的源文件。
5. 目标先写入同卷暂存目录；校验通过后同目录原子改名，再注册并切换。
6. 失败或取消时清理暂存目录，源空间始终保持不变。

数据库 schema 升级仍由正常的数据库打开流程完成。迁移层不维护第二套 SQL，也不修改已发布 migration；v0.3.2 的未发布 schema 变更继续合并在公共 revision 2 中。

## `.aiyspace` v1 导出格式

首个格式是无压缩、可顺序读取的 `.aiyspace` 二进制容器：

```text
AIYSPACE-V1\n
header-length + header-json
directory/file/hard-link records...
end-record
```

Header 和每类 record 都有独立 runtime schema。Header 记录格式版本、产品版本、数据库 revision、空间身份、文件数、存储字节数和展开字节数；每个文件 record 后跟原始字节和 SHA-256，footer 再校验完整内容摘要。归档路径必须是规范相对路径；禁止绝对路径、`..`、Windows 保留名、符号链接、设备文件和重复冲突项。

导出时先冻结一个不可变空间上下文，等待写操作收敛，并通过 SQLite snapshot/backup 生成一致数据库。对象按内容摘要只写一次；`temp`、WAL/SHM、锁文件、可重建缓存、应用级凭据和连接设置不进入容器。导出全程使用流式 I/O、字节/文件上限、进度和取消信号。

不使用 ZIP 是有意的：媒体对象通常已经压缩；顺序容器无需把中央目录或整个归档载入内存，也能在写入每个文件时立即做摘要校验。硬链接作为独立 record 保存；目标卷不支持硬链接时按普通文件恢复，并按展开字节数预检磁盘空间。

## 空间导入事务

导入复用当前迁移的“暂存 → 校验 → 注册”阶段，但不能直接信任压缩包：

1. 先校验 magic、header 和数据库 revision，并同时限制归档大小、展开大小、文件数、目录数和单文件大小。
2. 只写入新建的暂存目录，逐文件流式计算摘要并验证媒体/数据库边界。
3. 拒绝高于当前应用支持范围的数据库 revision；旧的已发布 revision 只通过正式 forward-only SQL 迁移。
4. 首版恢复模式保留空间 ID；若本机已有同 ID 空间则停止并要求用户处理，不能静默覆盖。
5. “复制为新空间”需要单独的、schema-aware 身份重写事务，不能只改 `library.json`。
6. 完整验证后原子提交并注册；失败、取消或崩溃恢复只清理经过严格路径验证的暂存目录。

这使旧版迁移和归档导入共享“暂存、校验、注册、切换”的安全边界，但目录迁移与 `.aiyspace` 协议仍各自版本化。
