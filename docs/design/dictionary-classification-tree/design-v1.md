# 词典分类树设计 v1

> 状态：概念评审稿
> 日期：2026-08-05
> 范围：桌面端词典的分类维护，不包含普通 Facet 管理

## 0. 结论

词典分类不再固定为“一级 + 二级”。新版采用递归树：

- 根节点在界面中称为**大类**；
- 大类以下统一称为**分类**；
- 任意分类都可以继续创建**下级分类**；
- 分类路径只用于定位和展示，例如 `身材 / 姿态 / 手势 / 双手动作`；
- 稳定标识不包含可变路径，移动分类不会改变稳定标识；
- 词条仍只精确归入一个分类节点，跨维度描述继续使用普通 Facet。

当前的 `PRIMARY_CLASSIFICATION + SECONDARY_CLASSIFICATION` 只适合两级结构，不能继续作为运行时分类模型。它可以保留为旧内容包的导入映射，但浏览、编辑、筛选和素材目录都应改用分类树。

## 1. 术语

| 界面术语   | 含义                                       |
| ---------- | ------------------------------------------ |
| 大类       | 没有上级分类的根节点                       |
| 分类       | 树中的任意节点，包括大类和所有下级节点     |
| 下级分类   | 当前分类的直接子节点                       |
| 分类路径   | 从大类到当前分类的名称链，仅用于定位和显示 |
| 当前层词条 | `categoryId` 精确等于当前分类的词条        |
| 包含下级   | 当前分类及全部后代分类中的词条集合         |

界面文案不再使用“领域”。“子类的子类”仍称为“下级分类”，通过完整路径区分层级。

## 2. 设计目标

1. 不限制实际层级深度，任意分类都可以继续细分。
2. 一眼看清当前分类的位置、直接下级和词条影响。
3. 移动、合并、停用不会破坏稳定 ID、旧词条修订或历史引用。
4. 内容包提供初始分类，本地空间可以安全调整并看到来源原值。
5. 分类树只负责主要目录；材质、颜色、对象、状态等交叉维度仍由 Facet 表达。

## 3. 主界面

主界面沿用词典已有的三栏工作台，不使用大卡片或独立设置页风格。

### 3.1 页面头部

- 返回词典
- 标题：分类管理
- 汇总：大类数、分类节点数、词条数
- 搜索：同时查大类、分类名称、英文名和稳定标识
- 主操作：新建大类

### 3.2 左栏：大类

- 只显示根节点；
- 数量为该大类整棵子树的词条去重数；
- 支持同级排序；
- 选中大类后，中栏展示它的完整分类树；
- 停用的大类默认隐藏，可通过筛选查看。

### 3.3 中栏：分类树

- 使用 disclosure chevron、树枝线和缩进表达任意深度；
- 每行包含拖动手柄、名称、包含下级的词条数和更多操作；
- 拖动只改变同级顺序；跨父节点拖动等价于“移动分类”，必须进入影响确认；
- 提供“全部折叠”和“新建子类”；
- 行菜单包含：新建下级分类、移动、合并、停用；
- 搜索命中深层节点时自动展开祖先链，但不改变用户保存的展开状态。

### 3.4 右栏：分类检查器

检查器始终显示完整路径，并分为三块：

1. **基本信息**
   - 中文名称
   - 英文名称
   - 稳定标识（只读）
   - 上级分类
   - 是否在分类选择中启用
   - 来源内容包、查看原值、恢复原值
2. **下级分类**
   - 直接下级数量和列表
   - 新建下级分类
3. **词条**
   - “仅当前层 / 包含下级”切换
   - 搜索和列表
   - 包含下级时显示每个词条实际所在分类

底部放置低频动作“合并分类”和“停用此分类”，不与保存按钮争夺视觉优先级。

### 3.5 前进后退导航

分类管理是词典中的完整页面，不是词典概览的临时面板。导航位置使用：

```ts
{
  surface: 'classifications';
  classificationId: string | null;
}
```

- 从词典概览进入分类管理时 `push`；
- 树加载后首次自动选择的默认分类以 `replace` 写回当前项，避免产生“未选择分类”的中间历史；
- 用户主动切换大类或分类节点时 `push`，前进后退必须恢复准确节点并展开其祖先链；
- 从分类检查器打开词条时，词条详情进入新历史项，后退恢复原分类节点；
- 创建分类后选中新节点属于新的用户结果，进入历史；
- 合并导致当前分类消失、请求 ID 无效或树为空时，以 `replace` 修正当前项；
- 搜索词、根节点排序、树展开、是否包含下级、词条内搜索和所有操作对话框不写入页面历史。

## 4. 核心规则

### 4.1 层级与计数

- 分类可以同时拥有直接词条和下级分类；不强制词条只能挂在叶子节点。
- 树行显示 `subtreeTermCount`，即当前分类及全部后代中的去重词条数。
- 检查器同时提供 `directTermCount` 和 `subtreeTermCount`。
- 大类汇总同样使用子树去重数。
- 计数由一次集合查询返回，禁止逐节点 SQL 或逐行 IPC。

### 4.2 新建分类

- “新建大类”创建根节点。
- “新建子类”以当前选中节点为上级。
- 中文名必填；英文名可后补。
- 稳定标识由系统生成并始终只读，避免手工键值破坏内容包映射和历史引用。
- 同一上级下不允许出现规范化后完全相同的启用名称。

### 4.3 移动分类

- 修改“上级分类”或跨父节点拖动都会打开影响确认。
- 整棵子树原子移动，下级节点的相对顺序不变。
- 稳定标识、词条 `categoryId` 和历史引用不变。
- 禁止把节点移动到自身或任一后代之下。
- 确认前显示：当前位置、新位置、下级分类数、涉及词条数。

### 4.4 排序

- 拖动默认只在同一上级内排序。
- 键盘和行菜单提供“上移 / 下移”，不依赖拖动才能完成操作。
- 排序使用稀疏 `sortOrder`；批量重排在一个事务内完成。

### 4.5 合并分类

- 用户选择一个目标分类；源分类不能是目标的祖先或后代。
- 源分类的直接词条迁移到目标分类；已核准词条生成新的不可变修订。
- 源分类的下级默认整体移动到目标下面，不自动按名称递归合并。
- 如果目标已有同名直接下级，确认前要求逐项选择“保留两个 / 改名 / 合并”。
- 迁移完成后源分类进入停用状态，不物理删除。
- 全部写入、修订、目录投影和 change event 必须在同一业务事务中提交。

### 4.6 停用与恢复

- 停用后不再出现在新词条的分类选择器中，但历史词条和旧修订仍可读取。
- 含有启用下级分类时，不能只停用父节点；用户需要迁移下级或确认整棵子树停用。
- 含有当前词条时，先提示迁移或保留为历史分类。
- UI 不提供硬删除；恢复后保留原 ID 和稳定标识。

## 5. 数据模型方向

建议通过下一条前向迁移重建 `term_categories`，核心字段如下：

```text
id                  stable, immutable
stable_key          stable, immutable, unique
parent_id           nullable self reference; null means 大类
name_zh
name_en
sort_order
state               ACTIVE | DISABLED
source_kind         LOCAL | CONTENT_PACKAGE
source_pack_id      nullable
source_release_id   nullable
source_hash         nullable
local_override_json nullable
created_at
updated_at
disabled_at         nullable
```

约束：

- `parent_id <> id`；
- repository 在事务中检查完整祖先链，拒绝循环；
- 索引 `(parent_id, state, sort_order, id)`；
- `term_revisions.category_id` 继续指向精确分类节点，不改为路径字符串；
- 包来源节点的本地修改作为空间级覆盖保存，更新内容包时不静默覆盖；
- 分类变更继续记录 change event 和 tombstone。

P0 使用 SQLite recursive CTE 一次返回树、祖先路径、后代集合和汇总计数。先测量真实数据规模；只有发现递归查询成为瓶颈时，才增加 closure table，避免预先引入双写复杂度。

## 6. 旧数据迁移

1. 每个原 `PRIMARY_CLASSIFICATION` 值转换为一个根节点。
2. 每个原 `term_categories` 组合转换为根节点下的分类节点。
3. 只有一级分类的旧记录直接指向根节点。
4. `term_revisions.category_id` 保持指向迁移后的同一逻辑分类。
5. `PRIMARY_CLASSIFICATION` / `SECONDARY_CLASSIFICATION` 是 v0.3.0 内容格式的角色投影，导入时转换为树节点。
6. 运行时浏览和编辑不再从 Facet system role 推导分类路径。
7. 文件投影中的 `TERM_DOMAIN / TERM_TYPE` 迁移为递归 `TERM_CATEGORY` 目录上下文；稳定 term/material 身份和文件对象不变。

## 7. IPC 与组件边界

建议的 renderer 组件：

```text
DictionaryClassificationScreen
├─ ClassificationHeader
├─ RootCategoryList
├─ ClassificationTree
│  └─ ClassificationTreeRow
├─ ClassificationInspector
│  ├─ ClassificationIdentitySection
│  ├─ ChildClassificationList
│  └─ ClassificationTermList
├─ MoveClassificationDialog
├─ MergeClassificationDialog
└─ DisableClassificationDialog
```

建议的 typed IPC 行为：

- 获取分类树及计数；
- 新建大类或下级分类；
- 修改名称和启用状态；
- 同级排序；
- 移动子树并返回影响预览；
- 合并分类并返回冲突预览；
- 停用 / 恢复；
- 按分类查询“仅当前层 / 包含下级”的词条。

进入分类管理时最多进行一次树查询；行展开、选择和计数不得触发逐项请求。分类浏览、素材库和词条列表的现有加载路径在实现前必须分别测量。

## 8. 验收重点

1. 可以创建 `大类 / 分类 / 下级分类 / 更深分类`，没有固定三级上限。
2. 移动含三层后代的分类后，整棵子树结构、词条归属和稳定 ID 正确。
3. 不能把分类移动到自身后代中。
4. “仅当前层”和“包含下级”的计数、搜索结果一致且无重复。
5. 合并已核准词条会产生新词条修订，旧修订仍可追溯。
6. 停用不会物理删除分类、词条、历史引用或媒体。
7. 内容包更新不会覆盖空间内的分类调整，且可以查看或恢复原值。
8. 词条编辑器显示完整分类路径，选择器可搜索任意层节点。
9. 大库浏览不新增逐节点 IPC、逐项 SQL 或首屏额外请求。
