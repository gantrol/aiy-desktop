# 05：本地空间、备份与恢复

## 空间是什么

一个本地空间包含注册信息、SQLite 数据库和受管对象目录。`libraries/index.json` 记录可切换的空间；每个空间至少包含：

```text
<library-id>/
├─ library.json
├─ library.sqlite3
├─ objects/sha256/
└─ temp/
```

空间切换应从应用入口完成。切换或退出前，等待后台模型任务结束，或明确取消并确认状态已经收敛。

## 导出和导入完整空间

在空间切换器中选择“导出本地空间”，保存 `.aiyspace` 文件。应用会先等待当前空间写操作收敛，再创建一致的 SQLite 快照，并逐文件写入和校验归档；导出不会修改当前空间。

恢复或换机时选择“导入本地空间”，再选择应用数据目录之外的目标文件夹。应用会在目标卷的暂存目录中顺序读取、校验文件摘要、空间身份和数据库，全部通过后才注册并打开。若本机已注册同一空间 ID，导入会停止，不会覆盖现有数据。

`.aiyspace` 包含空间数据库、创作历史和受管媒体对象，但不包含应用级账号凭据、连接设置、缓存或生产内容包源。内容包仍通过内容包导入器独立安装。

## 离线目录备份

1. 退出应用，并确认没有仍在运行的生成、导入或文件同步任务。
2. 复制整个 `AIY` 用户数据目录，至少保留 `libraries/index.json`、目标空间的 `library.json`、`library.sqlite3` 和 `objects/sha256/`。
3. 应用完全退出后，`library.sqlite3-wal` 应为空或不存在；非空 WAL 表示空间还不能作为稳定快照迁移。
4. 在另一份测试用户数据目录中恢复并打开，检查词条、素材、图集和创作结果。

不要只复制 SQLite，也不要在应用运行时直接复制或编辑数据库文件。不要把用户空间备份放入仓库的 `library/`、`media/` 或 `content/` 目录。

## 从旧版桌面应用迁移到 Store 版

Store 版使用独立的应用数据目录。首次打开空空间时，它会显式列出旧版 `%APPDATA%\AIY` 以及已安装 `AIYImageTools.Dev` 预览包中可迁移的空间；也可以稍后从空间切换器重新进入“迁移旧版空间”。

1. 先完全退出旧版 AIY。
2. 选择要迁移的空间和一个应用数据目录之外的持久目录。
3. Store 版将空间复制到暂存目录，保留可复用的硬链接，检查数据库版本、关闭状态、完整性和副本一致性。
4. 只有校验通过后，副本才会改为最终目录、注册并打开；旧空间保持不变。

旧注册表中本来就位于应用数据目录之外的空间可以原地注册，不需要复制。迁移不会自动导入生产内容包，也不会删除或改写旧应用的注册表。

## 恢复和缺失数据库

恢复时优先复制完整空间目录，再通过“打开本地空间”选择它。已注册空间如果缺少预期的 `library.sqlite3`，应用会报告不可用并保持零写入；它不会静默创建替代空库。

迁移只接受应用明确支持的已发布数据库 revision，以及当前版本仍可识别的开发 revision。未知版本、非干净关闭或完整性检查失败的数据库会保持原样并停止迁移，不会被猜测修复或替换为空库。

优先使用 `.aiyspace` 做日常备份和换机；直接复制目录和“打开本地空间”保留为离线恢复手段。内容包只承载可分发内容，不承担用户数据库、创作历史和媒体对象的整库迁移。

## 隔离测试空间

为避免污染真实资料库，可以设置：

```powershell
$env:AIY_USER_DATA_DIR = 'D:\AIY-test-data'
npm run dev
```

当前构建与验收目标只有 Windows Desktop x64 Store MSIX。测试结束后删除测试目录前，先确认其中没有需要保留的用户数据。
