# Capture & Notes

The bundled **Capture & Notes** entry uses `com.aiy.clipboard-capture`; **Clipboard History** uses the separate `com.aiy.clipboard-history` identity. Both belong to the host-owned **AIY Built-in Tools** directory. The clipboard entry inherits existing enablement and clipboard grants when introduced, preserving device-local history. Clipboard History starts recording when enabled and authorized; enabling Capture & Notes does not enable Clipboard History. History management remains available during a pause or when the plugin is disabled. Both packages stay at `0.1.0`; the application stays at `0.5.10`. No library database migration is introduced.

## Tools and notes

Open Extensions → Features → AIY Built-in Tools → Capture & Notes → Feature. The default **Tools** tab groups region capture, new note, open image to edit, clipboard to note, and image stitching above the existing temporary-file list. These actions use compact icon buttons with tooltips and accessible names; the capture arrow exposes delayed capture. Capture history has its own tab; clipboard history is a separate tool page. The capture-permissions action opens the existing permission panel; it does not grant permissions or start recording. Directory membership and external package rejection follow [the source policy](extension-source-policy.md).

Opening a still PNG/JPEG validates the existing image editor limits and creates a temporary image that opens directly for annotation. Clipboard images enter the same editor, while clipboard text opens an editable note; an empty clipboard reports an error without creating a note. The explicit paste action uses the existing temporary-file service and does not require background recording. Import cancellation creates nothing. Failed new image imports remove their partial temporary copy; a successfully saved image remains available if opening its window fails. Existing Markdown/general-image import entries retain their previous behavior.

The screenshot action **Edit in note** uses the same local image editor. Crop, rotation, flips, shapes, arrows, pen, highlight, text, numbering, mosaic, blur and output sizing operate on a retained original; completion returns to the desktop pin, where conversion to a text-and-image note remains available. The editor exposes explicit local OCR and QR recognition; recognized text can be reviewed, copied or opened as a note, and QR URLs never open automatically. This connects capture, pinning and local annotation as in [Snipaste](https://www.snipaste.com/) and [PixPin](https://pixpin.cn/docs/pin/base-use); it does not imply feature parity or native interaction acceptance.

Screenshot pins carry the selected physical rectangle through capture delivery. The host converts it once to device-independent coordinates and accounts for the pin's 8-DIP inset, so the displayed image begins at the selected location. The window retains image dimensions separately from text-note size presets and may extend beyond screen edges while keeping a draggable portion visible. Pointer dragging uses the local press position and native window coordinates, then native cursor positions, avoiding mixed global coordinate systems on scaled displays. File and clipboard images open around the pointer. New automatic titles use the localized image source and a timestamp; old `Clipboard.png` titles receive a readable display fallback without renaming stored user content.

Editing expands the same pin window to usable working space. Loading retains the image preview; finishing or cancelling restores the pin dimensions and the position relative to any deliberate editor movement. Converting to a text-and-image note clears image-only window sizing. The petal entry provides the shared tooltip context required by the editor toolbar. Editor rendering failures keep a visible return action; an outer rendering boundary supplies retry/hide controls instead of leaving an empty transparent window intercepting clicks. These are source-level fixes; native window hit testing still needs acceptance.

Image stitching accepts 2–16 PNG/JPEG/WebP files with reordering, vertical/horizontal/grid layouts, spacing, and transparent/white/black backgrounds. Work is bounded to 100 MiB of input, 32 million decoded/output pixels, a 16,384-pixel output edge and 25 MiB PNG output. A worker generates the preview and the result enters the temporary image editor. Scrolling capture and screen recording remain unfinished; cross-device clipboard remains explicitly deferred.

## Activation and permissions

Enable Clipboard History in the extension center and grant its required clipboard history permission: recording starts automatically, with no second recording switch. Required permission status is declared consistently in the package and host runtime contract; existing permission decisions remain intact. The legacy `recording` field remains readable in existing indexes but no longer gates clipboard collection. Capture history continues to use its separate recording preference. Referenced-image preservation has its own optional grant and switch; screen capture permission belongs to Capture & Notes and is not needed to record clipboard changes. Exclusions accept Windows process names, with or without `.exe`, separated by commas. An unknown source is skipped when exclusions are configured.

The **Pause recording** menu offers 1, 5 or 10 minutes, or until the next launch. A paused page shows the resumption time or next-launch condition and an immediate **Resume recording** action. Pauses belong to the current main-process lifetime: closing a window, switching libraries, or disabling/re-enabling the plugin does not clear them; elapsed timers or an actual application restart do. Timers are rechecked on system wake, and activation/permissions still gate collection after expiry. Pausing does not persist another off switch, overwrite settings, or depend on successful shortcut registration. Configuration updates keep the current capture/paste session, reject in-flight pre-pause collection, and reset the native clipboard sequence so resumption does not import paused content.

The page distinguishes disabled, missing permission, starting, recording, paused and stopped states. Recording is reported active only after the Windows helper acknowledges its configuration; failed startup exposes a retry action. Status keeps updating while a selected history item holds the list stable. Permission controls open the existing permission panel without granting access automatically. Opening history remains possible after native initialization fails.

Sensitive-content exclusion remains automatic for the recognized privacy formats before reading text or image payloads. The Windows history opt-out formats follow [Microsoft's clipboard format contract](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats); `Clipboard Viewer Ignore` is also recognized, as used by [KeePass](https://keepass.info/help/kb/faq.html). This is not password detection: unmarked passwords from other sources cannot be reliably identified. Users can exclude source applications or temporarily pause; no content is sent to a model to classify secrets.

The optional capture shortcut is Ctrl+Alt+X; capture and clipboard history each have a tray entry. Ctrl+Alt+V opens clipboard history, and Ctrl+Alt+B pastes the next queued item when a queue exists. Registration failure is reported; the plugin does not replace another shortcut. Disabling the plugin, locking the session, or suspending the device stops the native session; revoking a permission stops its affected capture/collection operations. Resume starts with subsequent clipboard changes rather than importing the current clipboard. History is device-local; permission grants follow the active library's existing plugin registry.

While enabled, the native helper remembers the last eligible foreground window identity for explicit paste actions, including when background clipboard collection is off. It does not read that window's content. Paste writes the selected payload, waits for shortcut modifiers to be released, activates and rechecks the target, then sends Ctrl+V. Windows focus restrictions and input isolation can reject this; the payload remains available for manual paste. Queue advancement is user-triggered and occurs only after successful delivery; it is not a timed batch typing operation.

## Storage and image ownership

`userData/clipboard-history` contains an atomic JSON index and UUID-scoped records. Each record owns its text/HTML body and, when available, a complete PNG. A SHA-256 digest is checked when opening, copying, or adopting a record. Missing or changed bytes produce an error rather than an empty image.

Payloads are flushed before the index is replaced. Capacity eviction first commits the replacement index and durable deletion intents, then removes the retired payloads. Failed cleanup remains accounted for and is retried before later mutations. Unknown files are never treated as disposable based on their absence from the index. A malformed index, or a missing index in an existing history directory, fails closed instead of silently rebuilding an empty store. Backups must include the entire history directory.

The default limits are 512 MiB and 1,000 records, with no age expiration. Settings allow 32–512 MiB, 50–1,000 records, and 0–365 days of retention (0 disables expiration). Fixed entries are excluded from automatic eviction and expiration. Operations that use originals serialize with writes and eviction. Search scans complete text bodies on demand, with bounded reads and cancellation when a newer query arrives; it does not load images for the list. Selected-image bytes are loaded only on selection or explicit retry. This is a resource-bound implementation, not a measured performance claim.

Native events have one unacknowledged snapshot at a time and coalesce intervening changes. Text and HTML are each limited to 262,144 characters; image output is limited to 24 MiB and 20 million pixels. Clipboard collection recognizes Windows privacy formats before reading payloads. It cannot identify every password or classify private content from pixels.

Actual PNG or bitmap data is normalized in the native helper. Opt-in file preservation handles one local PNG/JPEG/BMP reference from FileDrop or HTML. It rejects network paths and reparse points, does not open plain-text paths, and never fetches remote URLs. Unsupported or unavailable references remain references. Saved image copying supplies PNG/bitmap content without stale HTML image URLs, so a target cannot prefer an expired URL over the saved pixels. Native image copying does not promise original FileDrop semantics, animation, vector editing, or proprietary representations.

## Capture and adoption

The Windows helper freezes the display under the pointer and presents a native rectangle selector. Releasing the pointer retains the selection: drag inside to move it, drag an edge/corner to resize, or drag outside to replace it. The adjacent native toolbar uses icons with accessible names and shortcut tooltips for **Copy**, **Pin to desktop**, **Edit in note**, **Save as…**, **Reselect**, and **Cancel**, plus window/control/current-display/previous-region selection, size/ratio controls, magnifier and color picking. Controls use system fonts and colors; labels resolve from the existing English and installed language catalogs. Window/control selection is an explicit action, not automatic hover selection.

The optional global shortcut initializes a centered selection. Arrow keys move by one physical pixel, Shift+arrows resize, and Tab reaches the toolbar. With selection focus, Enter/Ctrl+C copies, Ctrl+T pins, Ctrl+S exports, Space edits, R reselects, M toggles the magnifier, and C picks color. Escape/right-click first cancels an unfinished drag, then clears the selection, then exits. Cancel exits directly. Repeated capture requests focus the existing visible selector. User selection no longer expires after two minutes; helper heartbeat, permission revocation, lock/suspend, shutdown, and display removal/scaling changes still end the session.

Copy, desktop pinning, editing, and file export are separate actions. Only **Copy** writes the clipboard. Authorized recording adds that output to history; recording being off does not implicitly open a pin. A failed history update reports that copying succeeded and leaves the crop available for retry/export. Retries of the same selection reuse their request identity, including a history commit followed by failed cleanup. Pin/edit requests also reuse a temporary-content identity so a failed window opening does not create repeated copies. Editing opens the existing temporary PNG editor directly; completion returns to the pin, with its existing copy and conversion actions. It does not return to the original screenshot selector yet.

Save-as cancellation and action failures return to the retained selection. Buttons are disabled while a delivery is pending; only a successful action ends the selector. Temporary saves remain under the existing capacity and input-protection rules. Choosing a new region gives subsequent deliveries a new identity. Full-display pixels never cross the helper boundary or enter the stored original; the confirmed crop alone enters clipboard, history, temporary storage or export. Cancelling before an action creates nothing and leaves the clipboard unchanged.

Visible application/content windows are preserved in the frozen screen instead of hiding the main window. The helper attempts to restore the previous foreground window only while the selector still owns focus; opening a pin/editor does not bring the main workspace to the front. Foreground activation remains subject to [Windows restrictions](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow). The implementation still captures one display and does not implement cross-display stitching, scrolling capture, screen recording, editor-position insertion, or coordination with an active magnifier. Mixed-DPI, protected-screen behavior, native focus, high-contrast and screen-reader interaction require native acceptance before release.

History actions include search, copy/plain copy, explicit paste/plain paste, queued paste, text-copy editing, text merging, direct image editing, pin/unpin, batch deletion, clear history/system clipboard, export, opening an independent temporary image/note, and adopting into the selected library. Clearing history preserves fixed entries unless explicitly included. Images reuse the durable content-image import service; text uses temporary-note promotion. The target library is validated and held through adoption. Adopted content does not depend on the history file's lifetime. Reopening a history item currently creates a fresh temporary copy; text promotion does not yet provide a persistent retry receipt.

## Verification scope

Use the existing plugin unit, component and integration suites, relevant petal regression coverage, TypeScript, ESLint, production build, and Windows PowerShell C# compilation. Compile `windows-clipboard.cs`, `windows-capture.cs`, `windows-capture-tools.cs`, `windows-paste.cs`, and `windows-capture-icons.cs` together using Windows PowerShell/.NET Framework, matching the shipped launcher. Compiling the helper does not instantiate its forms or read the clipboard.

No new tests or manual UI checks are implied. Existing regression suites do not directly exercise this new native listener, selector, crash recovery, or filesystem fault cases. Those limitations must remain visible in delivery and release acceptance.
