# Codex 聊天搜索：需求与实现

调研日期：2026-09-15。入口为“Codex 今天努力了吗？”扩展中的聊天记录。

## 参考与取舍

- [Slack：Search in Slack](https://slack.com/help/articles/202528808-Search-in-Slack)：使用范围、作者、日期等条件缩小结果，支持会话内查找与短语搜索。采用明确范围和现有筛选控件；当前输入框保持字面短语匹配，不引入一套隐藏的搜索命令。
- [Microsoft Teams：Search for messages and more](https://support.microsoft.com/en-us/teams/chat/search-for-messages-and-more-in-microsoft-teams)：区分查找聊天与查找消息，Ctrl/Cmd+F 搜索当前会话，从结果跳到对应消息。采用两层搜索和消息定位。
- [Slack：search.messages](https://docs.slack.dev/reference/methods/search.messages/)：返回高亮标记以区分命中内容。这里采用本地文本范围计算和 Markdown 文本节点高亮，保留原文与代码格式。

以下为 AIY 的产品决策，不代表这些产品的全部行为或实现方式。

## 常见需求

| 目的                     | 本次行为                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 找到某个会话             | 列表按关键词、项目、分组、会话、归档、更新日期、工作区、分支及是否包含子代理筛选                           |
| 分清搜索对象             | 新增“全部文本 / 会话信息 / 消息内容”；会话信息沿用标题、摘要、首条请求和项目等元数据索引                   |
| 知道为什么命中           | 列表标题和摘要高亮全部命中；摘要截取命中附近文字；正文、列表、引用及代码中的文本也可高亮                   |
| 在长聊天中找到原话       | 会话内独立关键词和用户／助手筛选；承接列表搜索词；结果按消息从新到旧显示                                   |
| 读懂命中的前因后果       | 每条匹配消息提供“查看上下文”；读取该消息前后记录，定位到目标消息，并可向两端继续加载                       |
| 继续比较其他命中         | “返回搜索结果”恢复已经加载的结果及滚动位置；上下文读取不清除筛选条件                                       |
| 快速重新搜索             | Ctrl/Cmd+F 聚焦会话搜索；Esc 从上下文返回，或清除会话内筛选；清除按钮与“全部消息”可恢复阅读                |
| 不把未查完误报为没有     | 显示已加载的匹配消息数；尚有历史时附加 `+`，提供“更多匹配消息”或“继续查找更早记录”                         |
| 输入中文、代码或全角文字 | 输入法组合期间不提交中间搜索词；字面匹配忽略大小写，使用 NFKC 及空白归一化；不把关键词作为 HTML 或正则执行 |

会话列表继续使用本地索引；会话内筛选直接读取该会话的分页记录或旧版 JSONL，包括助手过程消息。两者的覆盖范围可能不同。列表的日期条件始终是**会话更新日期**；进入上下文后展示邻近消息，不套用角色筛选，以便读懂对话。

## 历史消息格式

本机 2026-09-15 快照包含约 36.4 万条 `ThreadItem`、3,936 个任务和 10,282 条用户消息。格式计数会重叠，仅用于确定兼容面：附件信封 1,349 条、应用内浏览器上下文 382 条、答复批注 251 条／268 个条目、ChatGPT 会话引用 13 条／37 条嵌套消息、问题回复 78 条、委派 11 条、语音 3 条、自动化 1 条、IDE 6 条、选区 4 条；另有 52 个计划和 2,218 个图片生成记录。助手输出中还发现 391 个 Git 指令、319 个批注指令、51 个文件引用、48 个内联可视化、17 个代码评论、13 个新任务引用、5 个收件箱项和 2 个写作容器。Markdown 中有 321 个 Mermaid 围栏，并存在 LaTeX、`details/summary`、本地图片和大量本地／网络／Codex 链接。

- 用户正文不再由单个标题正则截取。读取层先识别 Codex 消息信封，再分别保存用户请求和上下文块，覆盖附件／粘贴文件、应用内浏览器、IDE、选区、答复批注、异步问题回复、ChatGPT 会话引用、任务委派、语音输入、自动化运行和斜杠命令。上下文默认折叠，用户请求保持正文层级；嵌套会话中的 Markdown 列表、表格、引用和代码会重新按消息角色渲染。
- 助手消息保留 `turn_id` 与阶段。连续的工作过程按回合折叠，最终答复、计划和图片生成结果分别标记；索引包含这些可见内容，但图片生成记录在 SQL 投影时排除 base64 结果，只传状态、提示词和已保存路径。
- Codex 输出指令只作为历史数据解析，绝不执行。文件引用、批注、Git 操作、创建任务、代码评论、收件箱项、内联可视化和写作块会显示为惰性结构化块；解析器跳过围栏代码与行内代码中的相似文本。
- Markdown 继续使用 GFM，并补充 Mermaid、KaTeX 数学公式和安全的 `details/summary` 降级显示。HTTP(S) 链接通过现有外链接口打开，Codex 任务链接走应用导航，本地路径不伪装成可点击链接。
- 本地图片与图片生成结果使用进程内 HMAC 签名的 `aiy-media` 能力地址。协议端异步核对签名、绝对路径、扩展名、文件类型、真实路径、大小和禁用路径片段；远程图片不会在历史列表中自动请求，内嵌 base64 也不会进入 IPC 响应。

## 实现边界

- 沿用现有 IPC；消息请求新增可选关键词、角色、方向、锚点，响应新增可选原始位置和向后续记录加载的游标。旧请求保持可用。
- 分页记录按 ordinal 定位；旧版记录按文件字节边界定位。上下文默认读取至多 10 条目标及之前消息、10 条之后消息，不需要从最新记录一路加载到命中。
- 单次会话查找沿用 5,000 条候选／64 MiB 的分页记录读取上限；旧版文件以 256 KiB 块异步读取，单次最多 64 MiB。触及上限保留继续读取游标，不自动无限扫描。
- 分页数据库读取 `userMessage`、`agentMessage`、`plan` 和 `imageGeneration`。本地索引与会话详情复用同一解析器和同一搜索文本语义；解析语义变更会更新来源签名并自动重建索引。
- 函数调用参数、函数输出和其他内部协议项不作为聊天消息展示；未知类型会跳过而不是让整页解析失败。历史指令即使可识别也始终保持只读。
- 请求替换后忽略旧结果，后端在批次和文件读取边界检查取消。上下文返回复用已有结果；更改会话关键词不重新挂载用量组件。
- 所有新增文案进入英文基准与简体中文语言包。使用现有 shadcn 组件与主题语义色，不新增样式文件、数据库迁移或版本号。
- 当前为字面短语搜索，不支持布尔运算、正则、模糊／语义搜索、附件全文搜索、搜索历史或单条消息日期筛选。Markdown 高亮在解析后的文本节点中执行；跨格式节点的短语和只匹配链接地址等非显示文本的内容，仍可能没有连续可见高亮。

## 验证范围

使用 TypeScript、修改文件的 ESLint／Prettier 和生产构建检查契约与编译集成。未新增测试代码，未启动浏览器、MCP 或 UI 自动化。实际界面操作效果与大规模记录上的耗时不由这些静态检查证明。
