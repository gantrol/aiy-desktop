# Codex 用量历史保留

统计插件把已读取的用量事件、轮次和已生成的报告保存在自己的 SQLite 数据库中。Codex 会话文件只是导入来源；文件消失不代表已经记录的用量应被删除。

来源文件变空、缩短或在内容变化后丢失部分事件时，导入会保留已有历史，并记录 `history_retained`。后续导入继续合并新记录，避免文件重新增长后再次覆盖旧历史。相同毫秒可能包含多次请求，合并同时匹配用量及记录次数，不能仅按时间去重。没有发生来源收缩的完整重读仍允许更新解析结果。

报告通过既有提示显示保留状态。打开已有历史报告时，对这类来源保留已有额度观测；用户明确更改采样设置时才重新计算。保留并不证明原日志从未缺失，已生成的报告也不能代替全部逐请求事件。

计价汇总缓存同时标识费率表和计算规则版本。费率或计算规则改变后，下次统计从已保存的逐请求事件重新计价，未变化的会话文件仍可复用导入缓存。已有历史报告保留生成时的快照，不在普通读取时重写。

API 等价费用与缓存节省金额按每次事件的模型、日期和 Standard／Fast 模式选取独立费率，不复用 Credits 或订阅额度倍率。费率表的 `apiFast` 保存 Fast 价格期间；`priority` 与 `fast` 继续由解析器归为 FAST。模式、该日期的费率或对应上下文档位缺失时保留未计价，不按 Standard 补算。长上下文的输入、缓存读取、缓存写入和输出分别使用对应加价，推理不重复计入输出。

额度周期导出的 `standardEquivalentApiUsd` 仍是额度折算指标：先取 Standard API 基准，再乘额度倍率；不把已含 Fast 加价的 API 等价费用再次乘倍率。该字段不代表按所用模式估算的费用。

2026-10-05 核对 [API 价表](https://developers.openai.com/api/docs/pricing)、[Fast mode](https://developers.openai.com/api/docs/guides/fast-mode) 与[更新记录](https://developers.openai.com/api/docs/changelog)：GPT-5.6 Sol 从 2026-07-30 起使用两倍 Standard 的 Fast 费率，2026-08-21 起对应促销费率；此前的 Fast 价格未补推。GPT-5.6 Terra／Luna 从 2026-07-30 的价格期间开始，GPT-6 各型号从各自发布日起计价。旧型号沿用目录的无日期基准；GPT-5.5 的 Fast 倍率为 2.5，GPT-5.5／5.4 未公布长上下文 Fast 价格的范围不外推。API 本次核对日期与 Credits 原核对日期分别保留。

新报告在 `pricing.apiRateMode` 中记录 `RECORDED_SERVICE_TIER`，CSV 同步带出 `api_rate_mode`，JSON 和比较快照保留计价依据。旧报告缺少该标识时沿用原 Standard 口径和金额，界面保留旧口径提示并提供重新统计入口；会话长度导出的费用口径也随报告选择。计算规则版本变为 3，复用现有缓存失效机制，无需新增数据库迁移或调整应用、插件版本。

用户主动清理本地索引仍会删除工作库中的用量事件，但会先完成明细备份，保留备份文件。备份失败则中止清理。清理后不会立即自动还原用户刚清除的索引；不能通过清理索引解决统计缺口。

## 任务历史的统计摘要

任务历史在选中会话时复用已有 rollout 解析，一次读取同时生成用量和时间摘要，不逐条扫描列表中的会话。摘要显示执行用时、Token 和 Credits，“详情”显示轮数、平均与最长轮次用时、完成与中止轮数、无结束记录、计时覆盖、上下文压缩次数、API 等价费用和模型用量。摘要缓存继续按来源文件与计价规则失效，切换会话沿用取消边界，不增加数据库迁移。

用时优先采用 `task_complete.duration_ms`；中止或旧记录缺少该字段时，仅在 `task_started` 与结束记录完整且顺序有效时采用起止差。未结束轮次不以当前时刻推算，避免把来源缺失误记成持续运行。总用时与平均值只纳入已计时轮次，保留零耗时及未知的区别，排除会话创建前的继承轮次；记录损坏、读期间文件变化或轮次元数据不完整时标明部分计时。该统计包含轮内工具及等待，排除轮次间闲置，不是首 Token 延迟。

聊天记录项默认提供整轮平均输出吞吐（tok/s）。列表先返回，再以每页一个请求从统计插件的已保留事实批量汇总；只读打开现存数据库，不创建数据库、迁移或扫描各会话日志。尚未导入统计的记录显示占位符；选中会话后的现有摘要读取会计算当前会话，并更新列表中该项。统计补充请求随筛选替换、离开页面或停用取消，迟到结果不能覆盖新筛选或已经更新的会话摘要。

吞吐仅采用同轮次有效配对的输出与耗时；输出增量沿用既有去重解析，不叠加推理 Token。完成和中止轮次都进入统计，未知用量、异常计时、损坏或不完整的来源不冒充零；详情保留配对覆盖与排除计数。保留历史的标记限制覆盖声明，但不丢弃已经保存且可以配对的事实；列表的事实导入时间早于聊天更新时间时同样标明部分记录。聚合使用输出总和除以执行秒数总和，不平均各轮速度。

上下文压缩后的配置重写、轮内模型或服务模式切换不结束当前轮次。解析分别维护配置归属和轮次边界，避免把配置之后的 Token 变成无归属用量而使整场会话吞吐不可用。下一次统计会重新解析旧缓存中缺少轮次归属或轮次元数据不完整的来源；未受影响的上一版解析缓存可继续复用。该修正不改写历史报告、不清理索引，也不新增数据库迁移。

用量报告在重新统计时保存吞吐总览与模型、推理强度、模式分组，模型 A/B 比较按选择重新汇总，CSV 与比较快照保留相同口径。按终态时间筛选轮次，报告上界不能被最后一次 Token 事件时间提前截断；旧报告普通读取不补造新指标。纯生成速度当前没有独立计时来源，详情显示未测量，不以整轮耗时或扣除工具时间推算。轮次起点现在允许缺失，由新增的缓存迁移 009 保留已知终态；既有迁移不重写，7、8 号历史缓存版本不复用。迁移前沿用明细备份，迁移保留事实与历史报告，只使派生缓存失效；不调整应用、插件版本。

会话正文外层必须保留可收缩的高度约束，正文独立滚动；统计详情展开后受面板高度限制并单独滚动，避免长会话或多模型明细撑开父级后被裁切。验证应分别记录静态检查、既有自动化测试及实际 UI 验收范围。

## 报告与比较口径

2026-10-04 修正范围如下。实现说明不替代测试或界面验收。

- 报告 `to` 使用调查截止时刻；逐请求事件查询可以提前到最后事件，但不能缩短报告声明的时段。重新调查历史报告通过报告 ID 读取原起止时刻、时区和粒度，生成新的报告。
- 整轮耗时总览由 A/B 分组结果派生，共用用户来源、轮次归属和终态范围。吞吐包含完成和中止轮次，耗时分布只包含完成轮次。缺失开始的终态保留并标记不完整；零耗时保留为零，没有可用时长才记未知。
- 来源异常数从持久化记录汇总，命中导入缓存不会清零。计数属于与范围重叠的整个来源文件，不能精确归属损坏记录的时间；没有任何可用时间的损坏来源也保留在异常数中。
- 普通报告读取和导出不刷新额度算法或官方速度参考、不写回历史报告。主动更改额度采样得到会话内计算视图，显示独立计算时间；当前计算视图可导出，原报告仍保留。会话内最多保留八组额度计算结果。
- CSV 固定列包含吞吐、配对 Token/耗时、完成/中止与排除计数、部分记录标记及报告范围；同时导出全局与分组吞吐。JSON 导出格式版本为 16。
- 历史按更新时间和 ID 分页，每页 50 条。读取历史不覆盖下次调查的参数；相对范围变化不会按枚举匹配到旧日期。旧版或缺少吞吐的报告显示重新调查操作。
- A/B 对比优先显示当前指标中位数、样本数和所选分组的吞吐覆盖，归一化费用表折叠。Standard/Fast 的模式差异不再作为异常。比较方案可删除，图表支持线性/对数刻度；相同值的累计比例一致。
- 会话长度汇总只使用所选来源，不从观察性费用区间推导新建会话建议。文件系统回退来源不冒充用户来源，比较中显示排除状态。
- 调查、同步 SQLite 查询和大段 JSON 编解码位于宿主管理的独立进程，文件操作保留异步接口。请求有队列和在途上限，暂停可越过等待队列；界面进度明确属于当前阶段。执行进程异常退出会拒绝在途请求，并将当前运行任务标为失败；后续主动调用可重新启动，不循环重试。宿主校验任务状态消息，通知回调异常不会向主进程事件循环抛出。此处描述故障隔离，尚无同数据集性能对照，不宣称提速。

## 可重算的明细备份

备份位于插件数据目录的 `backups/usage-facts-v1/`，独立于 `usage-cache.sqlite`。备份当前统计需要的逐请求 Token 分类、时间、模型、服务模式及推断标记、额度窗口和重置时间、来源身份、事件顺序与指纹，以及轮次起止、耗时、推理强度、压缩次数和数据完整性标记。零 Token 的额度观测也保留；备份前不按图表口径去重，不保存聊天正文、工具输出或整份 rollout。

扫描读取新日志前先备份现有明细，导入完成后再备份新增内容；需要迁移旧数据库时，在迁移执行前备份已有事实表。首次覆盖库中全部会话，之后按来源元数据增量更新，未变化的会话不重写。它只保护已经被统计插件读取过的数据，无法保全两次扫描之间就已被 Codex 删除的记录，也不能支持未来依赖未保存字段的全新统计。

每个会话保存当前和上一版 gzip JSONL，独立包含来源、用量事件、轮次及结尾校验记录。`manifest.json` 保存文件名、格式版本、SHA-256、记录数和压缩大小。当前版本完整写入并落盘后才原子替换清单，随后分批清理不再引用的旧版本；被工作库清除的会话仍保留在清单中。保留上限是每会话两版，并非固定磁盘容量；会话和明细增加时占用也会增长。

备份使用独立 SQLite 只读事务获得一致视图，单文件串行压缩，按 256 KiB 分块并施加流式背压。扫描备份支持进度与取消；失败会使任务失败，保留上次已提交的备份，重试可重新完成增量。初次备份不在普通报告读取时触发，只有必要的数据库迁移例外。

工作数据库文件缺失而备份仍在时，首次打开会重建空库并从清单恢复；明确清理已有索引不会触发这个入口。恢复逐文件验证来源、格式、SHA-256 和事件/轮次数量，以单个事务提交，失败整体回滚并保留重试标记。恢复后设置历史保留标志，再扫描日志时合并旧明细。现存数据库损坏时不自动覆盖它，应先按下面的恢复顺序保全原件，再在新数据目录恢复。

该格式是统计事实备份，不是聊天备份，也不是旧报告归档。源库版本记录在文件头中；从更旧或未来数据库产生的字段不能由当前数据库接收时，恢复会失败并保留文件，需适配对应版本后再导入。原始 SQLite/WAL 保全仍属于事故恢复步骤，不会因为已有统计备份而省略。

## 恢复顺序

1. 在任何写入、迁移、清理或正常关闭数据库连接之前，先保全原始数据库及当时存在的 `-wal`、`-shm` 文件。保持这一套原始文件不变，另做 SQLite 一致性快照。活动写入期间的普通文件复制不能直接当作一致性备份。
2. 在副本上检查历史报告、数据库空闲页和原始 WAL。WAL 会在 checkpoint 后被复用或清理；一致性快照只保留该时点的有效状态，不保存 WAL 的全部旧页版本。
3. SQLite `.recover` 的输出只作为候选。逐条验证字段、时间、来源身份和事件指纹；处理重复与冲突后，才合并到工作副本。汇总报告不能伪装成逐请求事件。
4. 检查数据库完整性、外键、旧报告保留情况，以及重新扫描后的历史保留结果，再以事务合并到正式数据库。保留恢复前快照和恢复范围记录。
