# AIY 浏览器伴侣

AIY 浏览器伴侣接收桌面端的通用交接，并在支持的网站自动填入。当前支持 ChatGPT Prompt，以及微博、微信公众号、小红书、X（Twitter）的正文和图片；扩展只填入内容，不点击发送、发布或模拟回车。

## 构建

本目录与桌面端共用 Git 仓库，依赖、版本及构建产物独立管理。以下命令在 `browser-companion/` 内执行；也可在仓库根目录运行 `npm run install:browser` 和 `npm run build:browser`。

    npm ci
    npm run build

在 Chrome 或 Edge 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，目录为 `.output/chrome-mv3`。扩展安装后，已打开的目标网页需要刷新一次。扩展 ID 固定为 `eagfpifnbkfmojcjfbababmlmagmdopg`。

## 连接桌面端

连接服务由 Electron 主进程管理，只监听 `127.0.0.1:47831`。不再构建、打包或注册独立 Native Messaging Host，也不要求用户另外安装 Node.js。AIY 实际退出时服务一并停止；Windows 上关闭主窗口但应用仍驻留托盘时，服务仍属于运行中的 AIY。

AIY 打开浏览器时先经过桌面服务的一次性 `/v1/connect/` 页面，通过扩展的外部消息接口保存授权，再跳转到目标网站。密钥只由扩展后台从私有存储读取；目标网页的 content script 只能请求后台为固定协议动作签名，并自行通过 CORS 取回结果，不会拿到密钥。主进程同时校验固定端口、精确网页 Origin、目标、时间窗和 nonce，拒绝重放或跨站请求。

## 使用

1. 在“上传 → 上传目标设置”为微博、微信公众号、小红书和 X（Twitter）分别选择已安装 AIY 伴侣的 Chrome / Edge Profile；ChatGPT 使用对应上传入口的 Profile 设置。若全机只有一个可用身份，AIY 将它作为初始选择。旧配置升级后保留原有路由，新增目标首次使用需要单独选择 Profile。
2. 在 AIY 输入 Prompt，或准备图文稿的标题、正文和图片，点击“上传”并选择目标。
3. 微博交接还必须启用桌面端“微博浏览器交接”扩展并授予 `browser.handoff:weibo`；该权限只放行本次捕获的正文和资产 ID。
4. AIY 持久化交接记录，并用所选 Profile 打开目标网页；目标 URL 携带随机 `handoffId`，批量准备还携带批次 ID 和标签组标题，不携带正文、图片或连接密钥。
5. 微信公众号按上传类型进入对应编辑器：“贴图”进入 `type=77`，“文章”进入 `type=10`，都在同一标签页继续交接。浏览器伴侣领取该 ID。JSON 响应与媒体元数据都经过 HMAC 认证，图片按原始二进制传输，并在创建 `File` 前校验长度和 SHA-256。
6. 用户检查内容后，自行决定是否发送或发布。

扩展弹窗不是主流程。它保留手动粘贴与“从历史填入”，用于自动交接未发生时的兜底。“从历史填入”只重试当前标签绑定的交接 ID；没有绑定时，请回 AIY 选择具体任务，不再猜测最近一项。桌面端的“AIY 伴侣历史”页会一直保留待交接、填入中和已填入记录，直到用户选择并删除。

## 批量准备

- `browserCompanionStageBatch` 接收同一来源的 1–4 份渠道候选，微博、微信公众号、小红书、X 各最多一份。候选正文、图序、内容类型和浏览器 Profile 在开始时固定；不会从源稿再次拼接。ChatGPT 不属于发布批次。
- 每个目标独立保存结果。图片不可用或目标权限不足不阻断其他目标；浏览器启动失败仍保留该交接。重开待填入任务沿用 `handoffId` 和已经准备的图片；已领取或已填入任务不会重复准备。
- 同一批次只读取一次水印配置，默认水印和指定水印都从这份快照解析，各目标开始前再核验水印是否仍启用。已准备交接的重开复用原媒体；尚未建立交接的失败项重新准备时属于新批次，会采用当时的水印配置。
- 在伴侣弹窗勾选“将同批准备的页面放入标签组”，浏览器会申请可选 `tabGroups` 权限。同一 Profile 内，伴侣将新开的批次页面放入同组；不同浏览器或 Profile 分开处理。未授权、接口不可用或分组失败时，继续使用普通标签，连接与填入照常。
- 分组只接收已有安全配对流程提供的标签 ID 和批次 ID，不搜索或移动用户原有标签。批量任务不能通过 `claim-latest` 领取。
- 本地批次收据保存成功项和失败项；`ready / claimed / delivered` 仍只表示待领取、正在处理、已填入，均不能证明发表成功。
- 尚未处理的目标记为 `NOT_ATTEMPTED`；已保存交接但打开结果不明确时记为 `OPEN_NOT_CONFIRMED`。进程中断不会伪装成平台确认失败。常规批次历史最多读取最近 1,000 份收据，删除交接会扫描所有收据并清理关联候选，不限于当前历史页。准备、重试和删除串行执行。

Chrome 接口依据：[tabs.group](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-group)、[tabGroups](https://developer.chrome.com/docs/extensions/reference/api/tabGroups)、[可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)。当前批量流程仍需在实际登录的 Windows Chrome / Edge Profile 上验收；自动测试不代替真实站点的编辑器兼容性验证。

## 当前边界

- 支持 `https://chatgpt.com/*`、`https://mp.weixin.qq.com/*`、`https://weibo.com/*`、`https://www.weibo.com/*`、`https://creator.xiaohongshu.com/*`、`https://x.com/*` 和 `https://twitter.com/*`。
- 回环协议、授权与任务存储不依赖操作系统；当前自动发现并定向启动浏览器 Profile 的实现仍只支持 Windows Chrome / Edge，其他平台启动适配列入后续待办。
- ChatGPT 交接填入 Prompt 和附件；微博填入正文和图片；微信公众号的贴图交接填入标题、描述和独立图片列表。文章交接填入标题、排版正文和文内图片，图片保留在各自段落之间。复制公众号正文仍可单独使用。
- 文章上传前先保存编辑内容；标题上限 64 字符，正文上限 10,000 字符，排版 HTML 上限 256,000 字符，最多 20 个不同图片资产。外部图片须先导入 AIY。文章封面由用户在公众号编辑器选择；贴图使用封面优先的图片列表。
- 文章正文使用编辑器粘贴事务写入，随后逐个替换图片占位。完整正文、图片位置和微信图片地址加载都核对成功后，才记录“已填入”。本地 `blob:` 预览不算上传完成。出现错误时保留网页中已填入的内容，并释放交接供用户处理。
- 单张图片最大 32 MiB，单次交接媒体总量最大 128 MiB；完整图片必须通过 SHA-256 校验。
- X 交接支持最多四个 PNG/JPEG/WebP/GIF 文件，可混合图片与 GIF；静态图片每张最大 5 MiB，GIF 每个最大 15 MiB。格式和文件大小在打开浏览器前校验。超过 280 加权字符的正文自动拆为原生连续推文，使用官方 twitter-text 计算中文、表情和链接长度，优先在段落、句末和词边界断开，保留全部正文，不拆开链接或组合表情。四个附件都放在第一条，上传完成后再追加后续帖子；全部正文与媒体确认后记录已填入。网页已有媒体时停止，须先手动移除。
- 小红书接入创作服务平台的“上传图文”。AIY 当前接入限制为 1–18 张 PNG/JPEG/WebP 图片、每张 32 MiB、总计 128 MiB，标题 20 个全角字符（40 个 Latin-1 字符）、正文 1,000 个 Unicode 字符。超限会报错，不截断或丢图。选定封面优先上传，其余图片保持原顺序；引用图片的编号随最终图序生成。先逐张上传、等待预览与上传进度结束，再填标题和正文并核对，成功后记录为“已填入”。
- 编辑器已有内容、找不到编辑器或交接开始时识别出多个编辑器时停止并释放交接记录；X 只继续填入本次自动创建的连续推文。
- 网页结构变化时停止，不尝试寻找或触发发送、发布控件。

## 站点适配器

- `src/lib/composer.ts` 只编排填入、占用检查和校验；站点行为通过 `composer-adapters/contract.ts` 与 `registry.ts` 注入。
- `chatgpt.ts`、`weibo.ts`、`wechat.ts`、`wechat-article.ts`、`xiaohongshu.ts`、`x.ts` 分别拥有编辑器定位、图片入口和上传确认；可复用 DOM 操作位于 `dom.ts`。
- X 的 `/compose/` 页面等待可见撰写对话框，不抢先填入背后的时间线。正文通过 Draft.js 的粘贴事件写入并按段落校验，避免重复文本和换行误报；上传进度仅在附件区域识别，排除字数进度圈。连续推文通过精确的 `addButton` 控件追加，并逐条核对已有正文、编辑器顺序和新编辑器空白状态。图片输入和预览限定在交接编辑器范围内。
- 微信公众号选择器、贴图类型和入口文案集中在 `wechat-config.ts`。贴图只使用 `.share-text__input` 和 `.image-selector` 对应的上传控件，不能回退到隐藏的文章或封面上传控件。
- `wechat-navigation.ts` 使用 `scripting` 权限，在页面主执行环境中精确点击对应创作入口。仅在该次同步点击期间将其 `window.open` 捕获为同源、指定路径和内容类型的同标签页导航，随后立即恢复原函数。交接 ID 和内容类型在登录跳转时保留；真正填入时以认证后的交接类型为准，拒绝在另一类编辑器填入。
- 文章正文定位与图片占位流程参考 [baoyu 的文章实现](https://github.com/JimLiu/baoyu-skills/blob/main/skills/baoyu-post-to-wechat/scripts/wechat-article.ts)。本实现额外核对全文、图片位置与加载状态；网站兼容性仍需对应账号实际验收。
- 导航消息由运行时 schema 校验，并限定到微信公众号顶层页面。新增站点应实现适配器，不向通用填入流程追加站点分支；不得在适配器中添加保存草稿或发表操作。

## 小红书图文

1. 更新桌面端和浏览器伴侣后，重新加载扩展并刷新小红书页面。在目标 Profile 登录小红书创作服务平台。
2. 打开 AIY 图文稿，准备标题、正文和图片，选择封面。在“上传 → 上传目标设置 → 小红书”选择该 Profile。
3. 选择“上传 → 小红书”。AIY 保存当前稿，准备可选水印图片，打开 `publish/publish?source=official&target=image`，浏览器伴侣逐张上传并填入标题和正文。
4. 在小红书检查图序、文字和账号，设置所需话题及可见范围，点击平台的发布按钮。
5. 若跳到登录页，登录后从 AIY 重新上传。上传失败或已有图片时，交接记录仍可重试；先清空平台编辑器中的图片，再打开图文发布页，使用伴侣“从历史填入”。“已填入”仅表示内容进入编辑器，不表示平台已经发表。

实现参考（2026-09-10）：[xiaohongshu-mcp 图文上传实现](https://github.com/xpzouying/xiaohongshu-mcp/blob/main/xiaohongshu/publish.go)用于核对先上传再编辑、逐图上传以及编辑器/预览定位；[xhs-mcp](https://github.com/Algovate/xhs-mcp)用于标题宽度、正文和图数限制的交叉参考；[OpenCLI 标题未持久化问题](https://github.com/jackwener/opencli/issues/1840)用于避免只赋 DOM 值就报告成功。以上为社区项目的一手实现与问题记录，不能替代当前登录账号的页面验收。当日创作服务平台上传页提示最大 32 MB，接受 JPG/JPEG/PNG/WebP。当前小红书图文交接已通过真实登录账号验收，范围止于填入和交接回执，不包含最终发表。
